## 技术摘要

当前 Lambertian 主链在几何和方向上采用同一个 Blender world-space：Gaussian 位置、GT 灯位、deformation 后 rotation 和光照点积都在这个世界坐标系中完成。Blender 与 runtime 的差异只发生在**相机局部坐标基**：Blender 相机为右/上/后，runtime rasterizer 相机为右/下/前。该变换翻转局部 Y/Z 两轴，行列式为 +1，所以不是左手系切换，也没有镜像世界坐标。

最终像素并不是单个 Gaussian 的颜色。每一个 Gaussian 先在 world-space 计算法线和辐照度，再以线性 RGB 颜色交给 2DGS CUDA rasterizer；rasterizer 按每个像素的 footprint、深度排序、alpha 和 transmittance 合成线性辐射量，最后才做一次 linear-to-sRGB 转换。

本报告确认以下核心路径：

1. 训练入口默认选择 photometric_lambertian，但在 photometric_start_iter 之前仍使用 original_sh。
2. gt_point 从 lights.json 只读取 light_pos_world；对 Blender area light 使用“中心点 + 1/r²”的点光近似。
3. Lambertian normal 由 deformation 后 quaternion 的 local +Z 得到，再按相机方向翻转到 camera-facing 一侧。
4. Lambertian 的 normal、surface-to-light direction 和灯位都在 world-space；没有 camera-space normal 与 world-space light 的混合点积。
5. rasterizer 进行 view-space 投影和合成；输出的 linear RGB 在 Python 端转换为最终 sRGB pixel。

最重要的限制是：当前 camera-facing normal 不是跨视角固定的 outward physical normal；gt_point 也不是 Blender area light 的完整物理模型。它们是明确的建模近似，不是坐标系错误。

## 5. 坐标系图：Blender、runtime camera、world normal 与屏幕

~~~mermaid
flowchart LR
    BW["Blender world<br/>右手系<br/>X/Y/Z 不变"] -->| "camera_to_world 原样写入" | T["transforms_*.json"]
    T -->| "inverse(C2W)" | W2C["Blender world-to-camera"]
    W2C -->| "相机局部基 D = diag(1,-1,-1)" | RW["runtime world-to-view"]
    RW --> RC["runtime camera/view<br/>+X 右, +Y 下, +Z 前"]
    BW --> L["lights.json: light_pos_world"]
    BW --> G["Gaussian: xyz / d_xyz / quaternion"]
    G -->| "W = runtime world-to-view rotation" | RC
    L -->| "不经过相机变换" | P["world-space Lambertian"]
    G --> P
    P -->| "颜色进入 rasterizer" | RC
    RC --> S["pixel x 向右, y 向下"]
~~~

### 5.1 坐标约定表

| 空间 | X | Y | Z / forward | 手性与用途 |
|---|---|---|---|---|
| Blender world | Blender world X | Blender world Y | Blender world Z | 右手；灯、物体、GT normal、Gaussian 位置共用 |
| Blender camera local | 右 | 上 | +Z 为后，-Z 为前 | 右手 |
| runtime camera/view | 右 | 下 | +Z 为前 | 右手；2DGS rasterizer 与像素射线使用 |
| image pixel | 向右 | 向下 | 不适用 | 图像索引，不是三维坐标系 |

从 Blender camera local 变为 runtime camera local 的矩阵是：

    D = diag(1, -1, -1)
    det(D) = 1

因此这是绕 X 轴旋转 180°的等价基变换，而不是 reflection；没有右手系到左手系的切换。

### 5.2 代码如何实现该基变换

dataset_readers.blender_c2w_to_camera_extrinsics()：

    W2C_blender = inverse(C2W_blender)
    R, T = 由 W2C_blender 构造 runtime R/T
    T[1:] *= -1

代数上等价于：

    W2C_runtime = D · W2C_blender

Camera 再将该矩阵转换成 row-vector layout 的 world_view_transform。camera_center 由 world_view_transform 的逆矩阵恢复，因此它仍是 Blender world-space 的相机位置。

相关代码：

- Blender C2W 到 runtime R/T：[dataset_readers.py](/home/han.li/reproduce/LumiMotion-perlight/scene/dataset_readers.py:62)
- world_view_transform 与 camera_center：[cameras.py](/home/han.li/reproduce/LumiMotion-perlight/scene/cameras.py:62)
- 运行时像素 rays：[cameras.py](/home/han.li/reproduce/LumiMotion-perlight/scene/cameras.py:74)

### 5.3 normal 的 world/view 往返

rasterizer 内部 normal 在 view-space；Python 输出 world normal 时：

    n_world = n_view @ world_view_rotation.T

由于 rotation 是正交矩阵，这等价于 n_world = W^T n_view。world normal 比较 GT EXR 时不再对 GT normal 做 Blender camera Y/Z 翻转。

相关代码：[gaussian_renderer/__init__.py](/home/han.li/reproduce/LumiMotion-perlight/gaussian_renderer/__init__.py:315)。

## 6. 光从哪里读取，在哪个空间 normalize

### 6.1 三种 light mode

| 模式 | 来源 | renderer 使用方式 | 是否学习 |
|---|---|---|---|
| learned_directional | 每 timestep 的 Parameter table | 归一化为 light-to-surface ray | 是 |
| gt_directional | lights.json 的 light_pos_world 与固定 scene center | center - light_pos，忽略距离 | 否 |
| gt_point | lights.json 的 light_pos_world | light_pos - Gaussian position，逐 Gaussian 计算距离 | 否 |

进入 point/directional GT 路径时，photometric_lambertian.py 只从每帧记录读取：

    entry["light_pos_world"]

然后按 frame_id 映射到最近的 timestep。来源：[photometric_lambertian.py](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:333)。

这一步不读取 Blender 的 light_rgb、原始 intensity、area_shape、area_size、area_size_y；这些未进入当前 Lambertian code path。

### 6.2 光方向定义

项目保存的 ray_dir 总是：

    ray_dir = light_to_surface

但 Lambertian 点积需要 surface-to-light：

    l = surface_to_light_dir = -ray_dir
    n_dot_l = dot(normal_world, l)
    shading = max(n_dot_l, 0)

对于 gt_point，代码直接构造：

    light_vector = light_position_world - gaussian_position_world
    distance = norm(light_vector)
    l = light_vector / max(distance, 1e-6)
    ray_dir = -l

对于 learned_directional / gt_directional，ray_dir table 会先做 F.normalize，再取负得到 l。

相关代码：[photometric_lambertian.py](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:491)。

结论：normal 与 l 在点积之前都是 world-space 单位向量；没有 camera-space normal dot world-space light 的混用。

### 6.3 光强、颜色与 Blender area light 的近似

当前 v5 公式中：

    gt_point:
      E_i = (I * C) / max(r_i, eps)^2

    learned_directional / gt_directional:
      E_i = I * C

其中 I 和 C 分别来自 CLI 的 photometric_gt_light_intensity、photometric_gt_light_color；不是自动读取 Blender light 的 intensity 或 color。

因此 Blender 的 area light 在 gt_point 模式下被近似为：

    area light center → point source position
    area light emitted power → manually supplied scalar I
    finite emitter / penumbra → 未建模

该近似是当前 RGB 偏差的重要来源，但不是坐标系不对齐。

## 7. Gaussian normal 如何进入 Lambertian

~~~mermaid
flowchart TD
    Q["Gaussian base rotation<br/>+ deformation d_rotation"] --> R["pc.get_rotation_bias(d_rotation)"]
    R --> NR["get_gaussian_normal<br/>n_raw = normalize(R(q) · local +Z)"]
    X["Gaussian world position<br/>xyz + d_xyz"] --> F["orient_normal_toward_camera"]
    C["camera_center in world-space"] --> F
    NR --> F
    F --> NF["n_photo: camera-facing world normal"]
    L["surface_to_light direction in world-space"] --> D["n_dot_l = n_photo · l"]
    NF --> D
    D --> S["shading = clamp_min(n_dot_l, 0)"]
~~~

### 7.1 原始 normal

Gaussian normal 从 rotation matrix 的 local +Z 轴取出：

    n_raw = normalize(R(q_deformed) · [0, 0, 1])

这里没有乘 world-to-camera rotation，因此 n_raw 是 world-space。

实现：[photometric_lambertian.py](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:92)。

### 7.2 camera-facing 定向

2D Gaussian 的切平面没有自然的正反面。为了与 rasterizer 的双面可见语义一致，Python 端使用：

    facing = dot(n_raw, camera_center - position) >= 0
    n_photo = n_raw                  if facing
              -n_raw                 otherwise

实现：[photometric_lambertian.py](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:109)。

render() 将 n_photo 传入 Lambertian renderer，而同时保留 n_raw 和 camera_facing mask 供诊断：

    photometric_normal              = n_photo
    photometric_normal_raw          = n_raw
    photometric_normal_camera_facing = bool mask

代码：[gaussian_renderer/__init__.py](/home/han.li/reproduce/LumiMotion-perlight/gaussian_renderer/__init__.py:139)。

注意：photometric_normal_camera_facing 名字容易误解；它保存的是 bool flip mask，不是一个 3D normal tensor。

### 7.3 正常与物理限制

这一 camera-facing rule 与 rasterizer 一致，能避免 local +Z 的符号歧义让 n·l 随意翻转。但它使 normal 依赖当前相机：

    同一个 Gaussian 在不同 camera center 下可能得到相反符号。

因此它适合当前可见面渲染和 2DGS 的双面代理语义；不等价于视角无关的封闭网格 outward normal。

## 8. 线性 Lambertian：从 albedo 到每个 Gaussian 的 intensity

### 8.1 albedo 的数值空间

photometric albedo 是一个 per-Gaussian sigmoid 参数：

    albedo_srgb = sigmoid(photometric_albedo_raw)

Lambertian renderer 在着色前转换：

    albedo_linear =
        albedo_srgb / 12.92                         if albedo_srgb <= 0.04045
        ((albedo_srgb + 0.055) / 1.055)^2.4         otherwise

相关代码：

- albedo 参数：[gaussian_model.py](/home/han.li/reproduce/LumiMotion-perlight/scene/gaussian_model.py:203)
- sRGB 转 linear：[photometric_lambertian.py](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:20)

### 8.2 每 Gaussian 的线性颜色

当前 v5 的 diffuse-only BRDF 是：

    c_i_linear = (rho_i_linear / pi) * E_i * max(0, n_i · l_i)

其中：

    rho_i_linear = albedo_linear
    E_i           = irradiance
    n_i           = n_photo world-space unit normal
    l_i           = surface-to-light world-space unit direction

实现：[photometric_lambertian.py](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:523)。

此处没有 shadow、visibility、indirect light、specular、area-light integration 或 exposure。它是标准单次直接漫反射项，不是完整 Blender Cycles/Eevee 成像方程。

## 9. 2DGS rasterizer：从 per-Gaussian color 到 per-pixel linear intensity

### 9.1 Python 交给 CUDA 的数据

gaussian_renderer.render() 为当前帧计算：

    means3D   = xyz + d_xyz
    rotations = rotation + d_rotation
    scales    = scale + d_scaling
    opacity   = opacity + d_opacity
    colors_precomp = c_i_linear

并将相机的：

    world_view_transform
    full_proj_transform
    camera_center

连同上述 Gaussian 参数交给 GaussianRasterizer。

代码：[gaussian_renderer/__init__.py](/home/han.li/reproduce/LumiMotion-perlight/gaussian_renderer/__init__.py:80)。

### 9.2 CUDA 中的投影和法线

CUDA rasterizer 对每个 Gaussian：

1. 用 viewmatrix 把位置投到 view-space；
2. 用 quaternion、二维 scale 和透视投影构造 2D footprint；
3. 取 quaternion rotation 的第三列为法线；
4. 将法线变到 view-space；
5. 使用视线方向做 camera-facing 翻转。

核心代码：

    p_view = W * p_world + camera_translation
    R = quat_to_rotmat(quat) * scale_to_mat(...)
    tn = W * R[2]
    cos = dot(-tn, p_view)
    tn *= (cos > 0 ? 1 : -1)

位置：[forward.cu](/home/han.li/reproduce/LumiMotion-perlight/submodules/2dgs_rasterizer_lumimotion/diff-surfel-rasterization/cuda_rasterizer/forward.cu:83)。

这个 CUDA facing 判定在代数上与 Python 的 dot(n_raw, camera_center - position) 同义，因此 Lambertian normal 和 raster normal 使用同一法线符号规则。

### 9.3 深度顺序与 alpha 合成

对于某个 pixel p，按前到后顺序处理 Gaussian i：

    alpha_i(p) = min(0.99, opacity_i * exp(-rho_i(p) / 2))
    T_i(p)     = product over j<i of (1 - alpha_j(p))

线性颜色累积：

    C_linear(p) = sum_i [ c_i_linear * alpha_i(p) * T_i(p) ]
                  + T_final(p) * background_linear

alpha 输出：

    A(p) = 1 - T_final(p)

源码在：

- alpha 计算：[forward.cu](/home/han.li/reproduce/LumiMotion-perlight/submodules/2dgs_rasterizer_lumimotion/diff-surfel-rasterization/cuda_rasterizer/forward.cu:401)
- color 累积：[forward.cu](/home/han.li/reproduce/LumiMotion-perlight/submodules/2dgs_rasterizer_lumimotion/diff-surfel-rasterization/cuda_rasterizer/forward.cu:439)
- alpha/normal buffer 输出：[forward.cu](/home/han.li/reproduce/LumiMotion-perlight/submodules/2dgs_rasterizer_lumimotion/diff-surfel-rasterization/cuda_rasterizer/forward.cu:450)

因此最终 pixel intensity 是多个 Gaussian 的可见性加权线性组合，不是“选最近点”或“每个 pixel 恰好对应一个 Gaussian”。

## 10. 最终 sRGB 输出与训练目标

### 10.1 一次、且在 alpha 合成之后的 sRGB 转换

rasterizer 返回 rendered_image 时，Lambertian 分支把它解释为 linear RGB：

    rendered_image_linear = rasterizer output
    rendered_image_srgb = linear_to_srgb(rendered_image_linear)

linear-to-sRGB 函数为：

    srgb = 12.92 * linear                              if linear <= 0.0031308
           1.055 * linear^(1/2.4) - 0.055              otherwise

实现：

- linear-to-sRGB：[photometric_lambertian.py](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:31)
- 调用点：[gaussian_renderer/__init__.py](/home/han.li/reproduce/LumiMotion-perlight/gaussian_renderer/__init__.py:290)

这避免了“先对每个 Gaussian 做 gamma、再 alpha blend”的错误次序。当前黑背景实验的 background=0 在 linear 与 sRGB 中数值相同；白背景的 1 也相同。

### 10.2 RGB loss 仍在 sRGB 域

普通 Lambertian Stage 1 的 image loss 是：

    L_rgb = (1 - lambda_dssim) * L1(render_srgb, target_srgb)
            + lambda_dssim * (1 - SSIM(render_srgb, target_srgb))

因此物理着色在 linear 域，优化目标的常规 L1/SSIM 在 sRGB 域。PBR 分支额外有 linear log loss；纯 Lambertian 分支当前没有相同的 linear RGB supervision。

代码：[train_stage1.py](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:692)。

### 10.3 loss 如何回传

由渲染图、alpha/depth auxiliary buffers 可得到：

    RGB loss             → albedo / normal / light / xyz / scale / opacity / deformation
    normal-depth loss    → raster normal / geometry / rotation
    distortion loss      → footprint/depth/geometry
    alpha BCE            → opacity / footprint / geometry
    light smoothness     → learned light table only

对 gt_point 与 gt_directional，light learning rate 固定为 0，灯位不更新。来源：[train_stage1.py](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:291)。

## 11. Auxiliary normal/depth 输出与 GT normal 评估的边界

~~~mermaid
flowchart LR
    A["CUDA allmap<br/>view-space weighted normal"] --> B["rend_normal_view<br/>可视化用"]
    A --> C["乘 world_view_rotation.T"]
    C --> D["rend_normal<br/>world-space weighted normal"]
    E["rendered depth"] --> F["depth_to_normal"]
    F --> G["surf_normal<br/>normal regularizer"]
    D --> H["GT EXR world normal evaluator"]
    I["Blender normal_exr<br/>Normal.X/Y/Z world-space"] --> H
~~~

rasterizer 输出的 normal 是：

    N_view(p) = sum_i [ n_i_view * alpha_i(p) * T_i(p) ]

它不是单位向量。Python 端将它转到 world-space 后，训练 normal regularizer 与 depth-derived surf_normal 点积：

    normal_loss = 0.02 * mean(1 - rend_normal * surf_normal)

评估时才单独做每像素 normalize，然后与 Blender world normal EXR 比较。

相关代码：

- raster normal 转回 world：[gaussian_renderer/__init__.py](/home/han.li/reproduce/LumiMotion-perlight/gaussian_renderer/__init__.py:315)
- depth-to-normal：[utils/point_utils.py](/home/han.li/reproduce/LumiMotion-perlight/utils/point_utils.py:9)
- normal regularizer：[train_stage1.py](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:673)

normal GT EXR 不进入训练 loss；它只用于事后评估。详细的 Gaussian-to-pixel/GT normal 对应关系见前述 08.16 matching 审计报告。

| 检查项 | 当前状态 | 依据 |
|---|---|---|
| Blender world 与 Gaussian world | PASS | 数据转换直接保存 C2W；Gaussian、GT 灯位不做 world-axis flip |

| ray_dir 正负号 | PASS | 存储 light-to-surface；shader 使用 -ray_dir 得到 surface-to-light |

## 13. 当前流程中最值得优先关注的风险

### 13.1 area light 被点光近似

lights.json 的 Blender light 可能记录颜色、强度和面积，但当前 gt_point 只采样中心 light_pos_world，并由 CLI 手工提供强度/颜色。渲染没有：

- 面光源积分；
- 光源可见性和软阴影；
- 自遮挡；
- 间接漫反射；
- 高光；
- 相机曝光/色彩管理拟合。

因此即使 world-space 坐标完全正确，RGB error 仍可通过 rotation、albedo 和 geometry 吸收。这是 per-light normal 退化的主要风险之一。

### 13.2 camera-facing normal 的相机依赖

同一 Gaussian 在相机绕到背面时可能翻转 normal。它对 2D surfel 的双面 rasterization 有效，但不满足一个物理封闭表面的唯一 outward normal 定义。

如果目标是 relighting 或与 GT normal 做严格物理比较，后续应同时输出：

    n_raw_world
    n_camera_facing_world
    rasterized_world_normal
    sign-invariant normal error

### 13.3 输入 soft alpha 与目标颜色

转换图像已经对 RGB 乘过一次 alpha；loader 的 no_bg black 路径会再次对 RGB 乘 alpha。该 alpha squared 风险集中在软边缘，会改变 RGB residual 与轮廓梯度，不是世界坐标问题，但会影响 geometry/opacity 学习。

### 13.4 v4/v5 可复现性

0811 训练的 v4 point-light 参数并不等于当前 v5 代码默认值。以后运行 insight render、normal eval 或续训时，应显式传入：

    --render_mode photometric_lambertian
    --photometric_light_mode gt_point
    --photometric_gt_lights_path ...
    --photometric_gt_light_intensity 1.0
    --photometric_gt_light_color 1.0,1.0,1.0

并在输出 README 写明使用的是 checkpoint-compatible v4 replay，还是 v5 重新训练结果。

## 14. 建议的下一步

1. 先建立一个固定 geometry、fixed GT light、只优化 photometric albedo 的 v5 控制组，验证线性颜色和标定光强的上限。
2. 单独实现 area-light sampling 或至少一个有限角半径 directional approximation；不要在同一实验中同时放开 rotation。
3. 增加 per-Gaussian raw/facing normal 以及像素级 normal 的统一 debug 输出。
4. 增加 sign-invariant normal metric，并建立 Gaussian 投影到 GT normal EXR 的逐点审计表。
5. 修正或显式保留 alpha premultiplication 策略，再比较 soft-edge/opacity 结果。
6. 在 v5 训练完成前，把 0811 保留为 v4 失败对照，不覆盖其 checkpoint 和渲染产物。
