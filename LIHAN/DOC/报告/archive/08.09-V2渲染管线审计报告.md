## 坐标系与相机结论

### Blender 到 transforms

`prepare_lh_dynamic.py` 将源 `camera.json` 每帧的 `camera_to_world` 直接写入 `transform_matrix`。对 120 帧数据逐帧核对：

- `transform_matrix == camera_to_world`，最大绝对误差为 `0`；
- 源相机旋转的行列式范围约为 `[0.99999968, 1.00000019]`，均为右手正交旋转；
- `camera_to_world @ world_to_camera` 的最大残差约为 `1.13e-6`；
- 相机内参 `fx=fy=1564.4444`，主点为 `(cx, cy)=(640, 360)`，恰为 `1280×720` 图像中心。

转换本身没有对世界坐标、灯位或物体位姿做轴翻转。

### Loader 的局部相机基变换

Blender 相机约定为 local `-Z` forward、local `+Y` up。Blender transforms loader 先求逆，再构造：

```text
R = -W2C^T
R[:, 0] *= -1
```

该操作等价于将相机局部基写成：

```text
C2W_lumimotion = C2W_blender @ diag(1, -1, -1)
```

这里翻转的是两个**相机局部轴**：`Y` 与 `Z`。`det(diag(1,-1,-1))=+1`，因此没有从右手系转换成左手系，也没有反射世界坐标。数值复算表明，Loader 实际得到的 camera center 与 Blender `position_world` 最大差值约 `5.3e-7`。

`Camera` 随后以 `(x, y, +z)` 构造 rasterizer ray；与上述局部 `Y/Z` 翻转组合后，中心 ray 正确对应 Blender 的 local `-Z` forward。因此：

- 相机位置正确；
- 中心视线方向正确；
- 图像上/下方向正确；
- 灯光和 Gaussian 仍在未翻转的同一世界坐标系中。

当前 loader 没有使用 JSON 的 `cx/cy` 来构造非对称投影，但 V2 主点正好居中，故不构成误差来源。

### `is_blender` 的影响

`--is_blender` 不会应用空间坐标变换。它只改变 deformation 的时间位置编码配置，并使训练不添加非 Blender 数据的时间噪声。因此它不是坐标轴问题的来源。

## 光源方向与坐标结论

V2 的 Blender 数据中，`lights.json` 记录的是 area light 的世界坐标中心，例如第 1 帧：

```text
light_pos_world = [3.8, -8.2, 3.0]
intensity       = 1800
area_size       = 1.25
```

启用 `--photometric_light_mode gt_point` 时，Lambertian renderer 使用：

```text
surface_to_light = normalize(light_position_world - deformed_gaussian_position_world)
ray_dir          = -surface_to_light  # light-to-surface propagation direction
shading          = max(dot(normal_world, surface_to_light), 0)
```

这是正确的 world-space 点光方向约定；没有多余的轴翻转或方向取反。第 1、60、120 帧的源数据中，光源、相机、物体位置均处于相同 Blender world space。GT 灯位控制实验也表明：固定 GT 灯位使 normal–depth mean 从 learned-light 的约 `43.48°` 改善至 `34.41°`，证实 learned light 方向存在问题；但它仍明显劣于原始 SH baseline 的 `19.01°`，故坐标或方向误差不是唯一、也不是主要根因。

## Lambertian 管线的实际模型与缺项

当前实现是：

```text
rendered_color = clamp(albedo_srgb * max(n·l, 0), 0, 1)
```

它不是 Blender area light 的完整漫反射渲染模型。下列源数据字段目前均未进入 Lambertian 着色：

- `light_rgb`；
- `intensity`；
- `area_shape`、`area_size`、`area_size_y`；
- 距离衰减；
- area-light 面积分；
- self-shadow / visibility；
- 间接照明；
- 每帧曝光或相机响应。

此外，训练目标图像以 8-bit sRGB 值读入，Lambertian 分支也在该数值空间直接相乘并 clamp；它不像 PBR 分支一样进行 linear RGB 转换。即使材质本身近似纯漫反射，Blender 图像仍受线性辐射度、area light、可见性和色彩管理影响；因此“材质 Lambertian”并不意味着 `albedo * n·l` 足以重建图像。

## Normal 与优化退化风险

Lambertian 分支从 Gaussian local `+z` 轴导出 normal，然后强制其面向当前相机。这与双面 2D Gaussian rasterizer 的符号约定一致，但该 normal 不是视角无关、符号稳定的物理世界法线。

训练切入 Lambertian 后，RGB loss 可以通过更新 albedo、Gaussian rotation、deformation 与 geometry 来补偿未建模的照明。参考实验显示：

- 固定 GT 灯位能改善 normal，但不能恢复 baseline；
- 解冻 rotation 后 normal–depth 误差出现最明显恶化；
- 允许联合优化时，RGB 会部分恢复，但 alpha、normal、dynamic/static separation 变差。

因此目前出现的漂浮 Gaussian、法线偏移、静态底座被动态化，更符合“外观误差被几何/rotation 吸收”的现象，而非坐标系翻转。

## 边缘 alpha 处理风险

数据转换时 RGB 已按 albedo alpha 预乘：

```text
rgb_out = rgb_input * alpha
```

之后 Blender loader 在黑背景且 `no_bg=True` 时又执行 `rgb = alpha * rgb`。这会使软 alpha 边缘接近 `alpha²`，压暗边缘。该问题主要影响轮廓和 alpha 邻域，不足以解释主体 Lambertian normal 的整体失败，但应在后续实验前修正或明确采用 straight-alpha 输入。

## 建议的最小下一步

不要继续尝试全局轴 flip。建议从原始 SH baseline checkpoint 开展以下最小诊断：

1. 固定 Gaussian xyz/scale/rotation 与 deformation；
2. 使用 GT world-space light position；
3. 仅优化 Lambertian albedo，并加入 linear-space 的全局曝光/强度；
4. 先记录该受限模型的 RGB 与 normal 上限；
5. 再单独增加 `1/r²`、area-light 采样和 visibility/shadow，每次只启用一项。

该顺序能明确区分“照明模型缺项”与“联合优化破坏几何/法线”，并保持原论文 SH baseline 的复现路径不受影响。
