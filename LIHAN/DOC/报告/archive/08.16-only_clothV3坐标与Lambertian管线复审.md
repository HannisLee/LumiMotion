# only_clothV3 坐标与 Lambertian 管线复审（0816）

日期：2026-08-16  
数据：`only_clothV3`  训练环境：`garuda / lumimotion-garuda`

## 结论

截至本次复审，`Blender → transforms → LumiMotion loader → rasterizer` 的相机和世界坐标链路正确；没有发现 world/camera 混用、左右手切换或全局轴翻转。GT directional light 也保持在原始 Blender world space，checkpoint 中的每帧光线由相同 world-space 灯位精确生成。

上次 08.09 报告后已经修复的两个问题是：

1. Stage-1 insight 的 view-space normal 不再在 Python 端额外取反；CUDA rasterizer 已经输出 camera-facing runtime-view normal。
2. GT EXR normal 被确认为 Blender world space，GT normal evaluator 和光强调标不再将其误当作 camera-local normal 转换一次。

这两处会影响 normal 可视化与评价，不会改变 Blender world 坐标、相机位置或 GT 灯位本身。

### 相机约定

Blender source camera 使用 local `+X` right、`+Y` up、`-Z` forward。LumiMotion rasterizer 使用 `+X` right、`+Y` down、`+Z` forward。因此 loader 使用的只是 camera-local 变换：

```text
S = diag(+1, -1, -1)
W2C_runtime = S @ W2C_blender
C2W_runtime = C2W_blender @ S
```

`det(S)=+1`，故这不是左手/右手切换，也不改变 world-space Gaussian、light 或 object 坐标。验证得到 runtime `+X=Blender right`、runtime `+Y=-Blender up`、runtime `+Z=Blender forward`。

## Renderer normal 链路

CUDA 端先计算 `tn = W_runtime @ R[:,2]`，随后依据 `dot(-tn, p_view)` 将 normal 翻到 camera-facing 一侧。Python Lambertian 端对相同 world normal 使用 `dot(normal, camera_center - position)` 做同一符号选择；两式完全等价（可见点除外的零测度边界）。

随后 `rend_normal` 仅乘 `W_runtime.T` 回到 world；`rend_normal_view` 保留 CUDA 的 runtime-view normal，Stage-1 insights 不再对它第二次取反。因此：

- Lambertian `N·L`：world normal 与 world light direction；
- `eval_stage1_normals_gt.py`：renderer world normal 与 Blender world-space EXR；
- insight PNG：runtime view normal，仅用于可视化。

没有发现 renderer 再把参与 Lambertian 着色的 normal 转到 camera space，也没有发现 light 经过不对应的相机变换。

## 点云与可见性 sanity check

初始点云 centroid 为 `[-0.000397, 0.156574, 0.623381]`，与 GT directional checkpoint 的 reference center 一致到 float32 精度。4,096 个初始点在 frame 1/60 全部位于视锥内；frame 120 为 99.05%。这排除了初始点云与当前相机使用不同世界坐标的可能。

## GT pass 光强调标

使用 120 帧真实 RGB、albedo、EXR normal 和 `lights.json` 的 world-space 方向校准：

| EXR normal 符号 | 推荐全局 irradiance | 平均前景 PSNR | 结论 |
| --- | ---: | ---: | --- |
| 匹配 2DGS camera-facing | `5.50435` | `16.318 dB` | 训练使用 `5.5` 正确 |
| 保留 EXR signed normal | `5.50441` | `16.322 dB` | 与前者几乎相同 |

两种符号的结果差异小于 `0.004 dB`，说明本数据的可见前景 normal 本身方向一致；不存在把 normal 多翻一次导致 5.5 偶然拟合的情况。每帧拟合强度范围是 `4.61–6.58`，这正是固定 directional approximation 忽略 area-light 距离、局部入射角变化、阴影和曝光后留下的系统误差。

## 仍然存在、但不属于坐标变换的限制

1. `gt_directional` 将移动 area light 的位置压缩为“对初始点云中心的一条方向”，不保留近距离点光的空间方向差、距离衰减、area size 或阴影；椅子头/椅脚的 `L` 近似误差可能很大。
2. 2DGS normal 的符号虽已和 rasterizer 对齐，但 normal / albedo / rotation / deformation 仍可共同吸收未建模的成像误差；固定 GT light 不会自动使 rotation 收敛到 GT normal。
3. 当前 Blender loader 仍未使用 `cx/cy` 做非中心主点投影。only_clothV3 的 `cx=640, cy=360` 正好居中，故本次数据无影响。
4. `camera_extent` fallback 没被 Blender reader 消费；only_clothV3 实际相机半径约为 `2.408`，不是零，故本次训练无此退化。
