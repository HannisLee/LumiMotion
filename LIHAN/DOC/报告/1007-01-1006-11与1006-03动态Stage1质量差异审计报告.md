# 1006-11 与 1006-03 动态 Stage1 质量差异审计报告

日期：2026-10-07（Asia/Tokyo）。对象：1006-11 jumpingjacks150_v5_spec32 与 1006-03 only_clothV4_Dynamic，均为 Stage1 35000 iter。

**主要判断：布料的主要问题是动态几何在换视角后不够稳定，而不是采集视角的 RGB 拟合普遍失败。人体也属于非刚体；“都是动态场景”并不意味着重建约束同样充分。** 两次训练使用同一原版代码、相同 Stage1 超参数、相同随机初始化，但相机采样、动态表面可见性、画面占比、光照变化和最终高斯分配差别很大。其中，短时间内的观察方向覆盖与薄布可见性，是目前最值得优先做对照实验的因素。

这项判断由以下事实支持：

- 统一重新渲染全部 15 个测试帧，only_cloth 的前景 PSNR 为 **36.48 dB**，jumpingjacks 为 **35.29 dB**。布料在对应时刻的采集视角能拟合得很好，但在固定相机播放同一模型时出现碎边、片状残影和杂乱法线。
- 相邻时间记录的相机光轴夹角中位数，jumpingjacks 为 **45.08°**，only_cloth 为 **3.49°**。前者短时间邻域内的观察方向明显更多；后者沿连续相机轨迹采集，视角与时间高度耦合。
- only_cloth 的红布可见区域平均只占画面的 **4.28%**；最弱的第 36 帧约 **255 像素，占 0.111%**。此时原图中的布几乎只是一条水平细线。
- only_cloth 的布料法线 MAE 为 **22.03°**，expected-depth MAE 为 **0.24179 世界单位**；全场景平均只有 **11.56° / 0.10218**。全图指标和静态椅子、底盘会掩盖动态布料的误差。

**这些证据足以定位问题类型，但没有完成“只改变一个因素”的新训练，因此不能给各原因分配确定的贡献比例。** jumpingjacks 缺少有效几何真值，目前只能确认其代表视角展示较整齐，不能断言其法线或深度真值误差一定更小。

## 2 直接打开 PLY 与动态渲染看到的是不同对象

`point_cloud.ply` 保存基础坐标 `self._xyz`，没有把某一时刻的 MLP 位移烘焙进去。实际动态渲染使用：

`x(t) = x_canonical + gate × MLP_xyz(x_canonical, t)`

旋转也加上网络预测的偏移；颜色另有时间相关调制。因此必须同时加载同一迭代的 `deform/iteration_35000/deform.pth`。canonical 是网络共同优化的参考表示，**不保证等于首帧、某个真实姿态或规整的平均网格**。

此外，这个 PLY 是 2D 高斯参数文件：只有两个尺度分量，`nx/ny/nz` 被写为零，渲染法线来自高斯旋转。普通点云或仅兼容标准 3DGS 的查看器，可能忽略形变、尺度或自定义颜色字段。查看器未知时，不能将其显示质量直接当作动态重建质量。

但本次已经同时检查了正确加载形变后的结果，**only_cloth 的问题仍然存在，不能全部归因于查看方式**。下图中，布料在自身测试相机、同一时刻渲染时接近 GT；同一时刻改用第一个测试相机后，布面出现明显片状结构。jumpingjacks 的代表帧在固定视角下仍保留较连贯的人体轮廓。

**推断：网络更容易用“随时间改变的几何和颜色”解释单条观察轨迹，而不必形成在所有视角下都正确的布面。** 这是最优先验证的原因。相邻角度本身不能证明其贡献大小，仍需保持布运动不变、只改变采集相机的重渲染对照。

薄表面又加重了约束缺失。第 36 帧的原始 [RGBA 图像](/home/lihan/data/LH-data/transfer-dynamic/only_clothV4_Dynamic/images/frame_0036.png) 中，布几乎侧对相机。按原版 loader 一致的 Alpha 缩放方式，在 640×360 下其红色材质代理仅约 255 像素。连续多帧处于很弱的可见状态时，增加训练次数不能补回没有拍到的布面细节。

红布面积使用对应 GT albedo 的 `R>2G 且 R>2B` 加 GT Alpha≥0.5 统计，来自该场景明确的红布材质；它是可见面积的代理，**不替代几何评测的对象 ID 掩码**。面积统计采用全部 120 帧／150 帧，不是只选代表图。

## 5 人体也非刚体 但运动结构和表示难度不同

人体开合跳不是一个整体刚体：胳膊、腿和躯干相互转动。不过，从建模角度，较大身体区域通常可以近似为局部刚性运动，轮廓、服装和部位颜色也提供了可追踪结构。红布则是大面积同色的薄表面，会下落、弯折、自遮挡和形成窄褶皱；接近侧面时几乎没有可见面积。这里的“折叠”是可见性和曲率变化，不代表真实拓扑发生了撕裂或变化。

这只是对两类重建难度的机制解释，**本次没有人体骨骼真值或两组 GT 运动频谱，不能定量断言布料的运动幅度／复杂度一定更高**。实际训练也没有使用人体骨骼、SMPL 或刚体标签；二者都走同一个通用 MLP。因此不存在“程序认出人体，所以给了人体专用模型”的证据。

该实现还有两个值得关注的具体限制：

1. **网络最终只让位置和旋转随时间变。** 虽然有 scaling head，返回时写的是 `d_scaling = scaling * 0`，动态 opacity 也是 `None`。这不会使布料原则上不可表示，但一个基础 surfel 的支撑范围不能随时间自适应；薄褶皱需要足够细的小高斯及正确旋转、可见性来表达。
2. **损失主要要求图像匹配和预测几何自洽。** 法线正则比较的是渲染法线与预测深度导出的法线，并没有读取 GT normal；depth distortion 也不是 GT depth 监督。8k 后启用这些正则，不能保证唯一正确的三维表面。位置平方正则和动态门控稀疏正则又会限制网络使用形变的代价。

二值分离整体上没有失效：代表图中红色动态区域覆盖布，35k 约 21.9% 的 cloth 模型高斯被门控标为动态，与 jumpingjacks 的约 21.4% 接近。**“布根本没有被识别为动态”不符合现有证据**；是否局部误分类仍需对象掩码与点对应验证。

代码证据：[形变网络及固定动态尺度](/home/lihan/reproduce/LumiMotion/utils/time_utils.py:190)、[图像与几何正则](/home/lihan/reproduce/LumiMotion/scripts/train_stage1.py:131)、[位移和分离正则](/home/lihan/reproduce/LumiMotion/scripts/train_stage1.py:165)。作者的 [LumiMotion 方法说明](https://joaxkal.github.io/LumiMotion/) 也将模型描述为通用动态 2DGS 和静动态分离；它支持本节的方法定位，不是这两个实验因果差异的证明。

## 6 光照和高斯分配会进一步放大问题

**光照变化是额外的解释歧义。** jumpingjacks 在训练时使用同一环境光条件；only_cloth 的 AREA 光随帧移动，同时相机和布也在变。Stage1 没有显式输入这些光源位置，使用 SH 和时间颜色 head 拟合明暗。该颜色 head 会调制基础颜色，因此高 RGB 分数允许一部分阴影／几何错误被外观补偿。这个机制有代码依据，但其实际贡献尚未通过固定光照对照量化。

**高斯分配的差异已直接出现在 35k 文件中。** 以下统计使用推理时 `sigmoid(2 × fea_0)>0.5` 定义动态点；尺度是 PLY 中 log-scale 的指数，是高斯轴尺度，不是网格边长。

| 模型统计 | 1006-11 jumpingjacks | 1006-03 only_cloth |
| --- | ---: | ---: |
| 总高斯数 | 146065 | 49672 |
| 动态门控高斯数 | 31238 | 10863 |
| 动态高斯最大轴尺度中位数 | 0.01202 | 0.05980 |
| 动态高斯两轴长宽比中位数 | 2.55 | 3.94 |
| 动态高斯 opacity 中位数 | 0.06098 | 0.04005 |
| loader 从训练相机计算的 extent | 4.29002 | 8.75984 |

cloth 的动态点只有对方约 35%，动态轴尺度在原始坐标中约大 5 倍，而且更细长。这与更大片、更散的布面表示相符，但**点数、尺度和单点 opacity 都不能单独证明质量差**，二者场景物理尺度、表面积和高斯重叠本来就不相同。即使用相机 extent 粗略归一，cloth 的上述中位尺度仍约大 2.44 倍；该 extent 是训练相机分布半径，不是 GT 物体尺寸。

相同训练参数也不会产生相同的空间细化行为：split/clone 用 `0.01 × scene_extent` 区分大小点，对应门槛约为 0.04290 与 0.08760。图像损失又按整幅图平均，布料的有效像素很少；相同屏幕梯度阈值未必为它分配足够细节。这些是需要优先检查增密策略的理由，而不是“把高斯加到 14 万就一定修复”的结论。

20k 起两组总点数均保持不变，因为增密／剪枝已经停止。cloth 被门控标为动态的点从 20k 的 12294 降到 35k 的 10863；这是门控类别变化，不能说成“最后又删除了 1431 个点”。只在当前配置下继续增加迭代，无法自动增加高斯数量。

## 7 初始化与材质不是已经证实的单一根因

默认随机方块是 `[-1.3,1.3)`，不会自动归一化 only_cloth。原版 `getNerfppNorm` 在 Blender 路径只计算相机 extent，未变换模型坐标；转换 JSON 中 `camera_extent=1.0` 也没有覆盖这里的实际计算。

only_cloth 的 baseline PLY 注释表明它是 **第 35 帧、11 个网格的表面抽样**。它的最高点约 z=1.9335；其中红布材质点约 **69.8%** 在随机方块之外。这意味着同样随机初始化对当前场景不是同样的几何先验，需要优化把点带到更远处。

但该 baseline 既不是本次训练输入，也不是全时序包围盒；jumpingjacks 没有对应几何 GT，不能证明人体全表面都在方块内。only_cloth 最终已经有许多点移到方块外，说明这不是硬截断边界。初始化偏差、前 1000 步不使用形变、20k 停止增密可能共同影响优化路径，但目前无法把初始化认定为主因。

已有 V4 对照也不支持“单纯换成漫反射材质就能解决”或“默认随机方块必然重建不好”：

| 已有 Stage1 对照 | 仅布料法线 MAE | 仅布料深度 MAE |
| --- | ---: | ---: |
| 1006-01 静态，原始材质 | 13.5544° | 0.031597 |
| 1006-02 静态，Lambertian | 13.6167° | 0.031342 |
| 1006-03 动态，原始材质 | 22.0285° | 0.241789 |

## 8 建议按以下顺序验证

优先让实验回答“是哪一种约束不足”，再调网络容量。以下均为下一步方案，本次没有启动新训练。

| 优先级 | 具体对照 | 控制条件与判断标准 |
| --- | --- | --- |
| 1 | 同一布运动，改为短时间内更多方向的采集 | 保持时间、材质、分辨率和原始每帧世界光源不变，只改变相机并重新渲染 RGB/Alpha。可以先使用每时刻多个相机的少量关键时刻实验，再比较独立视角。不能只打乱现有 JSON 的相机与图片配对。看布料 normal/depth 和固定相机的新视角是否改善。 |
| 2 | 单独消除照明变化 | 保持原相机和布运动，换成固定世界光照重新渲染。若几何改善，说明外观变化的混淆确有贡献；若仅 RGB 变化，不应宣称几何修复。 |
| 3 | 单独提高动态区域的监督权重 | 首先只改 loss 的前景／布料区域归一方式，并明确这是增加分区监督的变体。或独立做更紧构图的采集对照，同时正确更新相机内参。不能把裁剪、loss 和增密一次全改。 |
| 4 | 在覆盖改善后调整增密 | 先单独测试延长增密截止时间，再单独测试动态区域阈值／尺度条件。记录动态点数、尺度分布和新视角几何误差，避免只看训练 PSNR 或总点数。 |
| 5 | 分别隔离初始化和表示限制 | 全场景一致的坐标归一化对照需要同步变换相机、几何、灯位及 GT，并将深度误差还原到原单位；之后再独立检查 warm-up、位移／分离正则和动态尺度 head。GT 表面初始化只能作诊断上界，单独标记额外先验。 |

最低验收组合应包括：布料区域 normal/depth、预测覆盖率、对应测试相机 RGB，以及未参与训练的“相机×时间”组合。固定视角视频已有明确价值，但要量化其正确性，还需从匹配的动态 Blender 场景导出同相机同时间 GT。已有 `.blend` 的几何和动画必须核对后才能使用，不能只因文件名相近就视为对应真值。

对你提出的“是不是因为一个是人体”的回答是：**人体与布料的运动和表面结构确实可能导致难度不同，但本次更直接、更可操作的差别是采样覆盖、薄布的可见性，以及模型如何把有限监督分配给动态表面。** 现有证据最支持先改善观测条件，并将新视角布料几何作为验收目标。
