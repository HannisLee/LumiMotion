# 无GT静态SH预热与纯几何转移实施审查

2026-10-19；ushas / lumimotion-ushas。仅审阅TRAIN源码、历史计划及M05启动plan的固定配置，未读取任何外部GT指标，未启动训练或修改代码。按主控要求，M04/M05完整结果前不启动本轮正式实验。

## 建议冻结的实验含义

同一135 TRAIN、同一随机100k点和seed0运行一次新的静态SH预热，保存完成1000与16000次optimizer调用后的几何。两份起点进入同一个独立物理入口，各执行24000次物理更新，固定原已验旧光资产、相同转换和新Adam/RNG、同相对物理日程。唯一直接变量是预热几何起点；其点数、分布、opacity、scale和orientation共同构成初始化，不能称仅法线初始化变量。

预热共享一次长轨迹，短起点是其1000步前缀，避免两次预热的随机路径成为额外变量。长起点增加15000步预热成本，须另报；共同24000物理更新研究的是初始化质量，不是总算力相等。旧仅117 FIT的I00不参与初始化，不用失败refined灯，不按外部GT选预热终点。

## 原生SH保存边界

`scripts/train_stage1.py`的顺序为：相机/SH级别更新→前向和backward→报告与保存→densify/prune/reset→若iteration<opt.iterations则Gaussian和deform optimizer.step→scheduler/zero_grad。因此原baseline的iteration_1000实际存的是第1000次step之前、该步拓扑事件之前状态；16000终点又跳过最后一次step。`scripts/train_eldl_v3_baseline.py`已经如实声明N−1，不能将其旧文件重命名为actual1k/16k。

建议新增独立baseline入口及局部Trainer子类，不改共享Trainer和旧baseline。保留SH forward/loss、相机顺序、SH级别、native topology/reset时点和optimizer次序，仅做两项边界修正：本步Gaussian/deform optimizer在终点也调用；所有checkpoint统一移到该步optimizer、scheduler及deform.update之后。保存1000后继续运行至16000，不能在1000处重置优化器/RNG或停止拓扑。999的原warm_up−1自动保存也应在新子类中明确处理，不允许留下同名而不同语义的混合checkpoint。

实现上优先在新文件明确保留原train_step主体并审计diff仅上述边界，避免依靠临时把opt.iterations写成N+1、吞掉Scene.save等隐式猴子补丁。源码副本虽较长，但事件次序可以逐段审查。新输出写`checkpoint_semantics=post_optimizer_post_native_topology`、requested_step、completed_optimizer_calls和各组实际state.step摘要。

注意：原native在optimizer之前增密会替换Parameter，某些拓扑步的新参数不再持有本次backward梯度，所以“16000次optimizer调用”不等于每个参数16000次有效更新。不能为了美化计数把SH topology移到step后，那会改变预热算法。应保留原语义并记录参数组有grad数、step计数和拓扑事件；smoke验证在无拓扑步参数确有预期更新，在拓扑步新参数身份与记录一致。

静态SH的三个几何头`gaussian_warp/gaussian_rotation/gaussian_scaling`在首次前向前归零且requires_grad=False；共享编码和d_color仍按既有static_sh方式优化。`utils/time_utils.py`的d_opacity为None，几何零头使预热几何静态；这不意味着时变外观也静态。不得同时关闭d_color或改SH损失，把预热时长与观察模型修改混合。

## 只转移四类几何张量

| 属性 | 新物理初始化处理 | 代码依据与原因 |
|---|---|---|
| `_xyz` | 原始float32逐值复制 | 正式优化的canonical位置 |
| `_scaling` | 复制原始log-scale两通道 | 避免exp/log往返；不重新KNN估scale |
| `_rotation` | 复制原始四元数四通道 | 使用时由get_rotation归一化；不另投影/重定向 |
| `_opacity` | 复制原始logit | opacity属于此次几何初始化，不额外reset |
| `_albedo_dc` | 统一`RGB2SH(0.5)` | 现有_begin_physical本就如此，不继承SH DC |
| `_albedo_rest` | 对应N大小的全零 | 物理override_color路径不用SH高阶 |
| `_roughness` | 统一sigmoid反变换的0.75 | 与新Gaussian默认一致，物理Lambert路径不用它 |
| `feature` | 对应N×fea_dim统一−0.01 | 原binarization_init_value；物理shader不读binary feature |
| `_albedo_dc_stage1` | 不创建 | 直接load_ply会创建它并让training_setup增加额外组，应避免 |
| MLP权重、SH优化器、SH RNG | 全部不转移 | 两物理分支都新建同seed网络并冻结，使用新的共同训练状态 |

`GaussianModel.get_albedo`将DC通过SH2RGB得到sRGB，`scene/eldl_v3_photometric.py`再srgb_to_linear。因此统一sRGB 0.5对应线性rho约0.214041，不是线性rho 0.5。保持原转换，不顺手改成线性0.5。使用`override_color`的物理渲染显式传零形变，不调用deform或binary feature；这应通过一次真实前向的inactive梯度/数值检查确认。

推荐预热保存时额外生成只含上述四个CPU float32张量的纯几何包及JSON收据，作为物理加载唯一权重输入；原完整PLY与deform仍保留供预热审计。读取几何包用weights_only受限加载和精确key/shape检查。完整load_ply会加载颜色、feature、roughness并创建stage1 DC，不是最小纯几何转移方式。四张量检查N一致、有限、scale两通道、非零四元数、exp(logscale)有限且为正；不通过裁剪或规范化悄悄改变原几何。

## 安全加载插入点及状态重建

原构造链是`Trainer.__init__ → DeformModel新建/可能尝试load_weights → Scene(load_iteration=None) → create_from_pcd → training_setup`，之后StaticDL冻结几何头并建灯，再UnknownLight写初始审计，最后ELDL替换成固定旧混合光。Scene当前不shuffle相机，加载原随机points3d并保存input.ply。不能将预热PLY直接换进source/points3d.ply：BasicPointCloud路径只消费点/色并重新KNN初始化scale、单位旋转和0.1 opacity，会丢失所需几何。

最小插入点是新ELDL子类`super().__init__`完整返回之后、任何train_step或late-lr hook安装之前。在同一个现有GaussianModel对象上替换四几何Parameter及所有N相关非几何张量，保留`scene.gaussians is trainer.gaussians`，然后按原opt调用training_setup重建全新Gaussian Adam。显式清零max_radii2D、xyz_gradient_accum、denom，清所有param.grad、相机stack和visibility缓存。camera_extent来自同135相机；training_setup硬编码spatial_lr_scale=5，这是原语义，不能改成父SH自选值或scene extent。

随后立即调用同一_begin_physical，冻结整个新MLP，清DC状态；新Adam本来应为空。MLP的三个几何头严格零且全网requires_grad=False，物理不更新其optimizer。light_optimizer保持原固定灯lr0，无梯度和更新。再次核验Gaussian optimizer各组Parameter身份与当前模型一致、state为空；不要在已装LateLearningRate之后training_setup使hook捕获旧base/optimizer。最后安装相同晚期乘子，并保存physical_step0转换收据/几何快照。

不能直接复用旧main再传physical_start=0：旧正式gate明确只允许1000，旧guard也拒绝外部权重。应新增独立入口，正式固定physical_start=0，并保留其他安全门槛；不放宽旧入口、不借smoke_schedule绕过正式约束。此时iteration=1就是第一步物理，运行24000步；不能加载父iteration=16000后继续累加到40000，也不能再跑一段SH。

父类在super阶段已写“随机初始化/无模型权重”和100k初始点数记录。新入口必须在转换后更新实际entrypoint、`weights_loaded_from_parent=true`、四张量来源SHA、实际N、`gt_supervision=false`、没有转移颜色/Adam及真实physical_step。原source manifest仍可保留`init_weights_loaded=false`描述原随机数据源；不能把它当作本次模型没有加载权重的声明。Scene留下的input.ply只是原随机输入，应另存effective_initial_geometry及说明，避免误认为它是本次有效起点。

## 严格父来源清单与无GT护栏

预热源仍是原四项无GT135 TRAIN副本；物理源仍是绑定旧灯的六项源。两者images、points3d、transforms逐字节相同，frames恰好135且唯一、有序；manifest本身因用途不同可不同。父SH来源清单须绑定新入口和完整源码快照、native模块、原随机点云SHA、全部135 RGB/Alpha相机来源、静态几何头状态、seed、配置、实际更新计数以及actual1000/16000各纯几何包/完整PLY的SHA。默认仅接纳这一明确父实验的两个端点，不支持任意历史模型目录。

在读取权重前，独立入口先验证已登记父manifest路径和内容、当前source/父source的共同135输入一致，再检查端点与包SHA。护栏只增开确切父manifest、确切几何包及核验必需的确切收据文件，不把整个父目录递归加入允许范围。父目录可能后来出现外部评测，必须继续拒绝。拒绝路径逃逸、symlink逃逸、缺项、额外张量、117 FIT模型、GT标记、失败/未完成父训练、N−1旧保存语义及混入旧颜色/优化器字段。来源声明与哈希是可复查证据链，不能将任意文件自称no_gt当充分证明。

若需核验父deform零头，只允许父manifest精确绑定的deform文件读取，不将其权重装进物理模型。生成完成收据应等SH16000正常结束后一次性冻结；actual1000包虽早已保存，两分支仍共同等父实验完成与工程验收，避免长分支失败时形成不完整对照。

## 相机、RNG及共同物理日程

从同一Scene源得到相机顺序，按source_frame、image_name_train_light、fid、K/c2w/中心逐项核对135；无TEST相机、相同400×400/AREA/预缩小满码mask、黑背景。原Scene注释掉shuffle，真正相机抽样使用Python randint无放回stack。两模型点数不同会影响CUDA随机消耗，不能承诺全轨迹bitexact；应在所有构造和纯几何转换结束后统一重新seed Python/NumPy/Torch/CUDA并清viewpoint_stack，记录初始RNG和首轮135相机序列，保证共同相机采样序列。不得继承SH1000与16000不同的RNG或未抽完stack。

建议共同沿用已冻结M05的数值日程，但统一解释为物理步k，不随父SH年龄偏移：normal在k>2000，opacity detach从3001，visibility从5000，dist在k>8000；densify从>500且每100步，until20000，reset每3000且skip=0，normal_screen_exclude=0、plane/sparse=0；BVH interval1，bias0.03326199531555176，原photo depth_ratio1与expected几何副本不变。晚期m(k)在16000后下降，20000到0.1，保持至24000，xyz原名义30k衰减后乘子，其余活跃组从base重算。维持原step→scheduler→非终点topology/reset→save次序和next-step lr审计。

该共同物理24k日程与历史M05“总步前1000为SH”的阶段长度不同；两条新分支内部才是公平控制，历史M04/M05仅作背景。不能为了保留旧文件名而让长预热分支从16001开启高lr/normal/visibility或跳过reset阶段。

## 工程验收与末五点度量

先做CPU纯几何包schema、来源/拒绝错误父、路径逃逸、张量shape/有限、四组逐值复制、非几何初始化一致和空Adam审查。GPU仅在另行授权后使用主控统一编号做短smoke：同一新SH短轨迹保存两个actual端点，真实验证末步更新和保存后重载一致；两种N进入新物理入口，physical_step0/1、vis/normal/dist、topology/reset及保存边界均覆盖。审计active组有预期梯度，feature/rest/roughness/MLP/固定灯无有效更新，禁用旧stage1组，真实生产加载前向一致。无拓扑smoke逐组Adam.step应等于实际调用数；有拓扑情形按原native语义记录，不能一刀切要求相等。

预热固定保存actual1000，以及12000/13000/14000/15000/16000五个末段点，并附14999/15000/15100解释reset瞬态。SH末段尚有增密/剪枝和15000 reset，不能将这五点变化机械当作固定拓扑收敛阈值。完整135 TRAIN记录SH重建loss、AlphaIoU/coverage、point_count、expectedZ/GS相邻变化、拓扑事件；SH loss与物理censored loss不是同一目标，不能跨阶段直接相减当收益。纯几何和转换后统一rho/旧光的零更新观测分开报告，既看预热外观拟合，也看其转入物理后的初始几何/覆盖。

两物理分支固定保存step0及原关键事件，最终共同在20000/21000/22000/23000/24000五点做完整135 TRAIN诊断。RGB/Alpha误差与coverage使用同一观察Alpha固定分母，不因两模型点数或初始Alpha不同而改变有效区域。expectedZ/GS跨时间变化既报告共同有效区域，也报告原前景固定分母的缺失惩罚和覆盖，避免掉点带来虚假稳定。新旧起点的几何变化不等于GT准确；终点选择固定24000，不据任何外部指标选某个中间点或延长单组。

以上形成一次有限初始化检验，不承诺16k SH已经充分几何收敛或一定改善固定光训练。预热若工程失败、非有限或明显未恢复覆盖，保留失败并报告，不自动换checkpoint；24k物理若仍不稳定，结论保留预算/优化限制，不把两组末点相对改善自动写成用户几何目标已达成。
