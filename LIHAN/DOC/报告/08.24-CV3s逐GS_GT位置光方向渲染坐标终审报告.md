日期：2026-08-24  
服务器 / 环境：`garuda` / `lumimotion-garuda`  
渲染 / 训练主干版本：`1faccef`（前置基线 `22f0576`）  
主审计实验：`output/0824-04-CV3s-GTposition_perGSdir_3ncons`，iteration 35000  
对照实验：`output/0823-01-CV3s-GTlight_lambert_iter1_3ncons`，iteration 35000

工作区说明：审计期间另有并行任务在未提交工作树中扩展 normal evaluator 的 `--normal_source`，本报告没有修改或提交这些文件。该扩展只允许分别选择已有的 independent/GS normal，不改变训练、渲染或误差公式；双来源指标保存在各实验的 `normal_gt_eval_dual_audit` 目录。

## 1. 最终结论

本次终审没有发现 CV3s 的相机、光源、Gaussian、法线之间存在世界坐标错位，也没有发现光线符号、时间索引、checkpoint 恢复或 linear/sRGB 顺序错误。`gt_point_direction_only` 的实际前向是：

```text
surface_to_light = normalize(light_position_world[t] - deformed_gaussian_position_world[t])
shading = max(dot(camera_facing_world_normal, surface_to_light), 0)
```

光源位置与变形后 GS 中心均在同一个 Blender/runtime world space，公式和符号正确。

但“保存了 GT 光源点，所以每个 GS 获得了完整 GT 光照”这个前提不成立。当前模式只保证**从 GT 面积光中心到学习所得 GS 中心**的方向准确；GS 中心不是 Blender GT 表面点，原始灯又是 `AREA` 而不是理想点光源。面积、灯面朝向、距离能量、可见性、软阴影、间接光、非 Lambertian 材质和 Blender 色彩管理均未进入当前前向。因此它是“局部中心方向 oracle”，不是“GT light transport oracle”。

最关键的实验证据是：在 final geometry 上固定 Blender GT albedo/normal 做 15 个 test 帧的只读 GT-pass，逐点局部方向相对中心方向将前景固定强度 sRGB PSNR 从 `15.65 dB` 提高到 `17.42 dB`，线性域全局拟合 PSNR 从 `12.63 dB` 提高到 `15.67 dB`。这证明局部方向和坐标是有效的；但 `17.42 dB` 的上限仍很低，证明主要误差已经不在方向，而在剩余成像模型。

训练结果也符合这一判断：逐 GS 方向让独立 shading normal 的 GT mean error 从 `19.23°` 改善到 `18.36°`，却让 GS raster/geometry normal 从 `20.53°` 退到 `21.12°`，同时 RGB PSNR 从 `47.65 dB` 降到 `46.86 dB`。也就是说，更准确的方向确实改善了它直接监督的 shading normal，但没有自动修好几何；不完整的 RGB 模型和新的位置梯度又把部分残差转移给了 geometry、albedo 和 opacity。

最终判定如下：

| 审计项 | 判定 |
| --- | --- |
| 世界坐标、相机和光源对齐 | **PASS** |
| 帧号、fid、光源位置索引及 checkpoint 恢复 | **PASS** |
| `light_pos - deformed_GS_pos` 方向和 Lambertian 符号 | **PASS** |
| 作为“只改变局部中心方向”的前向消融 | **PASS** |
| 作为严格的单变量优化消融 | **有条件通过**：梯度图也发生了变化 |
| 作为完整 GT 点光 / 面积光传输 | **不成立** |
| “仅靠逐 GS 中心方向应恢复近乎 GT normal/geometry”的假设 | **FAILED** |

## 2. 审计范围与口径

本次是只读诊断，没有修改训练、渲染或数据代码，也没有启动新训练。审计内容包括：

1. CV3s 原始 `camera.json`、`lights.json`、`normal_exr` 与转换后 `transforms_train/test.json`；
2. Blender C2W 到 rasterizer W2C 的转换；
3. train/test 合并后的 120 个 fid 到 120 个光位的映射；
4. iteration 35000 的 Gaussian、deformation 和 photometric checkpoint；
5. 逐 GS 光方向、法线旋转、camera-facing 定向、Lambertian 和 rasterization 调用链；
6. directional 与逐 GS 方向两组 35000 iteration 的 RGB、独立法线、GS 几何法线和梯度轨迹；
7. final geometry 上使用 Blender GT albedo/normal 的 15 帧 test GT-pass。

`output/0824-05-CV3s-GTposition_perGSdir_lambert_default` 在审计时仍在 GPU 0 训练，因此本报告不使用其中间数值下结论。

## 3. 坐标、索引和符号审计

### 3.1 数据帧与时间映射

- train 105 帧、test 15 帧，并集严格为 source frame `1..120`，没有缺帧或重复帧；
- transforms 中显式时间严格为 `(source_frame - 1) / 119`，最大误差为 `0`；
- float32 fid 仍有 120 个唯一值，最近时间索引严格映射到 `0..119`；
- `lights.json` 键严格为 `0001..0120`；
- iteration 35000 photometric checkpoint 的 120 个位置与 `lights.json` 最大绝对差为 `0`；
- GT normal 文件的帧号同样严格为 `1..120`。

`Scene` 从 train 和 test camera 合并建立排序后的唯一时间表，见 `scene/__init__.py:99-104`；Lambertian renderer 用最近 fid 取索引，见 `scene/photometric_lambertian.py:311-313`。本数据的 120 个时间恰好命中，不存在“test 帧被挤到错误光位”的问题。

### 3.2 Blender 相机与 runtime world space

转换器只在**相机局部轴**上将 Blender 的 right/up/back `(+X,+Y,+Z)` 改为 rasterizer 的 right/down/forward `(+X,-Y,-Z)`，没有旋转或镜像世界中的点，见 `scene/dataset_readers.py:62-76`。

数值闭环结果：

- transforms C2W 与原始 `camera.json` C2W 最大绝对差为 `0`；
- transforms translation 与 `position_world` 最大绝对差为 `0`；
- C2W/W2C 互逆最大误差约 `1.13e-6`；
- runtime `camera_center` 与 Blender 相机位置误差约 `3.55e-15`；
- camera ray world 方向闭环误差约 `9.35e-8`。

因此 `lights.json` 的 Blender world position 无需再乘相机轴变换。若再对光位做 `diag(1,-1,-1)`，反而会制造错位。

### 3.3 GS 位置、独立法线与光方向使用同一个 world space

实际渲染中心为：

```python
means3D = pc.get_xyz + d_xyz
```

见 `gaussian_renderer/__init__.py:98`。同一个 `means3D` 同时用于：

- 独立法线的 camera-facing 定向，`gaussian_renderer/__init__.py:153-157`；
- photometric renderer 的 `position`，`gaussian_renderer/__init__.py:239-244`；
- rasterizer 的 `means3D`，`gaussian_renderer/__init__.py:289-299`。

独立法线先由 canonical GS rotation 到当前 deformation rotation 的相对旋转变换，再在 world space 与相机方向定向。Blender Normal pass 本身也是 world space，评估时没有额外乘相机矩阵。

### 3.4 光线符号正确

代码在 `scene/photometric_lambertian.py:597-619` 中执行：

```python
light_vector = light_position[None] - position
surface_to_light_dir = normalize(light_vector)
ray_dir = -surface_to_light_dir
ndotl = dot(normal, surface_to_light_dir)
```

这里 `ray_dir` 是物理传播方向（light-to-surface），Lambertian 使用的是相反的 surface-to-light 方向。命名容易混淆，但参与 `N·L` 的符号正确。iteration 35000 的实际前向与手工 `normalize(light_pos - means3D)` 最大误差为 `0`。

### 3.5 线性空间与 gamma 顺序正确

albedo 先由 sRGB 转线性，逐 GS 得到线性 Lambertian 颜色；rasterizer 在线性域做 splat/alpha compositing，最后只调用一次 `linear_to_srgb`，见 `gaussian_renderer/__init__.py:301-304`。当前背景为黑色，线性 0 与 sRGB 0 相同，不存在背景域混合问题。

## 4. 运行时数值证据

### 4.1 局部方向确实不是无关紧要的小修正

在 iteration 35000 的 16012 个 GS、120 个时间上：

| 统计项 | min | p05 | median | p95 | max | mean |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 局部方向与中心方向夹角 | 0° | 2.54° | 6.73° | 14.89° | 88.78° | 7.64° |
| 光源到变形 GS 距离 | 3.04 | 5.98 | 7.49 | 8.93 | 10.20 | 7.49 |
| 两种方向的截断 shading 绝对差 | 0 | 0.00048 | 0.0645 | 0.1702 | 0.8530 | 0.0719 |

方向修改对大多数 GS 有可测影响。极端 `88.78°` 并不是坐标翻转，而是学习所得 deformation/geometry 的尾部异常：`||d_xyz||` 的 median 约 `1.3e-8`，但 p95 为 `0.899`、最大为 `8.00`。这也说明“GT light position 到 learned GS position”不是“GT light position 到 Blender GT surface point”；learned position 偏离时，所谓 GT ray 也会跟着偏离。

CV3s 原灯为 `AREA`，`area_size=1.25`。在场景参考中心处，灯面半对角对应的角半径约为 `5.85°–7.81°`，与局部方向修正的 median `6.73°` 同量级。只取面积光中心并不能称为精确入射光线。

### 4.2 GT-pass：方向更正确，但完整 Lambertian 上限仍低

只读探针使用 15 个 held-out test 帧、iteration 35000 重建 depth 导出的 world surface point、Blender GT world normal、GT albedo 和前景 mask。它比较三种直接光模型；全局/逐帧强度均在线性域最小二乘拟合，固定强度列使用训练值 `5.5043499`。

| 模型 | 全局最优强度 | 全局线性 PSNR | 逐帧最优线性 PSNR 均值 | 固定 5.504 的前景 sRGB PSNR 均值 | `N·L<=0` |
| --- | ---: | ---: | ---: | ---: | ---: |
| 场景中心单方向 | 5.626 | 12.635 dB | 14.205 dB | 15.652 dB | 2.04% |
| 逐像素局部中心方向 | 5.276 | **15.674 dB** | **17.117 dB** | **17.416 dB** | 2.55% |
| 局部方向 + 朴素 `1/r²` | 254.91 | 13.818 dB | 15.334 dB | 不适用 | 2.55% |

逐像素局部方向相对中心方向：

- 全局线性 PSNR 提高 `3.04 dB`；
- 固定训练强度的前景 sRGB PSNR 提高 `1.76 dB`；
- 可见前景的方向差 mean / median / p95 为 `7.91° / 7.66° / 13.59°`。

因此，局部方向在相同坐标中确实更接近数据，不是实现反了。与此同时，它的固定强度前景 PSNR 仍只有 `17.42 dB`，逐帧最优强度仍在 `4.42–6.45` 之间变化。这直接表明方向之外仍有显著的能量、阴影、间接光和色彩映射残差。

朴素 `1/r²` 在本口径下反而下降，不能据此否定物理距离衰减；它说明把真实 AREA 灯再片面替换成“中心点 + `1/r²`”，而不加入灯面朝向、面积积分、visibility 和成像曝光，仍是错误的部分模型。

## 5. 训练结果的分解

### 5.1 RGB 与两类 normal 给出了不同结论

| 指标，iter 35000 | directional 3n | 逐 GS 方向 3n | 逐 GS 相对变化 |
| --- | ---: | ---: | ---: |
| 全图 PSNR | **47.6509** | 46.8617 | -0.7893 dB |
| SSIM | **0.998667** | 0.998375 | -0.000292 |
| LPIPS | **0.004784** | 0.005461 | +0.000677 |
| 独立 shading normal mean | 19.226° | **18.358°** | **-0.868°** |
| 独立 shading normal median | 15.603° | **13.145°** | **-2.458°** |
| 独立 shading normal p95 | 59.904° | **56.043°** | **-3.861°** |
| GS raster/geometry normal mean | **20.526°** | 21.122° | +0.596° |
| GS raster/geometry normal median | 13.523° | **13.361°** | -0.162° |
| GS raster/geometry normal p95 | **69.473°** | 70.979° | +1.506° |

SH 默认 2DGS normal 对照的 GS geometry normal 为 mean `12.542°`、median `8.866°`、p95 `37.418°`，明显好于两组 Lambertian geometry normal。这说明当前 Lambertian 分支虽然能用独立 normal 拟合 shading，却没有把该改善可靠地传回 Gaussian covariance/geometry normal。

逐 GS 方向实验的 best RGB 在 30000 iteration 为 `46.9644 dB`，因此 final 与 best 很接近；下降不是简单的“最后 5000 步崩坏”。另外全图 alpha 覆盖仅约 `17.2%`，全图 PSNR 受约 82.8% 黑背景显著抬高，不能把 `46–48 dB` 直接理解为前景物理重建接近完美。

### 5.2 逐 GS 模式改变了梯度图，不只是替换常量方向

这是本次发现的最重要优化混杂项。

`gt_directional` 的方向与 GS position 无关；`gt_point_direction_only` 使用：

```python
normalize(light_position - position)
```

其中 `position=means3D` 没有 detach。因此 RGB loss 除了通过投影/覆盖影响 geometry，还会沿着**光方向对位置的导数**直接推动 canonical position 和 deformation。代码中的 `detach_xyz` 发生在 photometric color 已计算之后（`gaussian_renderer/__init__.py:273-274`），也不能切断这条 shading-position 梯度。

这在完整物理可微渲染中不是错误，但在当前缺少 AREA/visibility/GI 的模型中，会使 geometry 移动去补偿错误的光照残差。它也意味着当前实验在“前向变量”上只换了方向，却不是严格的“优化图单变量”消融。

gradient audit 的训练后 10% 均值进一步支持这一点：

| 项目 | directional | 逐 GS 方向 | 变化 |
| --- | ---: | ---: | ---: |
| RGB L1 loss | 0.0009823 | 0.0010787 | +9.8% |
| RGB DSSIM loss | 0.0004336 | 0.0005273 | +21.6% |
| position `lr*||grad||` | `7.41e-7` | `9.20e-7` | +24.1% |
| albedo `lr*||grad||` | `2.44e-7` | `2.78e-7` | +14.1% |
| alpha 帧间绝对差 | `2.609e-4` | `3.614e-4` | +38.5% |

这些差异不能单独证明所有退化都来自新增位置梯度，但与“局部方向的 GT-pass 更好、训练后 geometry/alpha 反而更差”的组合证据一致。

## 6. 为什么方向正确仍不能恢复得非常好

### 6.1 第二个端点不是 GT：learned GS position 不等于 Blender surface position

光源端点来自 GT，但表面端点来自可学习 `pc.get_xyz + d_xyz`。其位置会被 RGB、alpha、distortion、normal consistency 和 deformation 正则共同改变，并且逐 GS 模式的光方向本身又会反向推动该位置。这是一个闭环变量，不是外部 ground truth。

若要得到真正的 per-pixel GT ray，需要 Blender depth/position pass 或有 GT 对应关系的动态 mesh surface point；当前数据只给了光源中心、normal/albedo pass，没有给每个 GS 的 GT surface correspondence。

### 6.2 数据是 AREA 光，当前只取中心方向

`lights.json` 明确记录：

- `source_type = AREA`；
- `area_shape = SQUARE`；
- `area_size = 1.25`；
- 原始功率 `1800`；
- 逐帧 `light_pos_world`。

当前模式只使用最后一项，并以手工拟合的固定白光强度 `5.5043499` 渲染。它没有灯面 orientation/matrix；即使想正确采样 AREA，也缺少决定发光面朝向的元数据。中心点方向不能表达同一表面点接收到的一束方向分布、软阴影和灯面余弦。

### 6.3 可见性、间接光和材质项缺失

当前颜色只有：

```text
albedo_linear / pi * fixed_intensity * max(N dot L, 0)
```

没有 visibility、cast shadow、self-shadow、indirect illumination、specular、roughness、环境光或 residual radiance。目标 PNG 则包含 Blender 完整渲染与色彩管理。优化器只能用 albedo、normal、position、scale、opacity 和 deformation 吸收这些误差，因而“RGB 很高”和“normal/geometry 正确”不是同一件事。

### 6.4 独立 shading normal 与 GS geometry normal 解耦

独立 normal 只控制 Lambertian shading；Gaussian rotation/scale 仍控制 splat covariance 和 raster normal。`photometric_normal_live` 的目标又是当前模型 depth 导出的、detach 后的伪 surface normal，不是外部 GT。这样可以让独立 normal 更平滑、更接近当前 geometry，却不能保证 geometry 走向 Blender GT。

本次双来源评估已经显示：局部方向改善独立 shading normal，同时 geometry normal 的 mean/p95 变差。后续报告必须始终分别写 `independent` 和 `gs`，不能再用一个“normal 指标”概括两者。

### 6.5 `photometric_normal_mv` 对这段 falling-cloth 序列的静态假设不成立

`scripts/loss.py:92-96` 把该项定义为静态场景多视角一致性；实现会把当前帧的 world point 直接投影到随机 partner frame，见 `scripts/loss.py:136-230`。但 CV3s 源场景包含 `Falling_Cloth`，并有 120 个 `.bphys` cloth cache。对象 transform 静止不代表 cloth 顶点静止。

因此跨不同 fid 直接假定同一个 world point 是同一表面点，会把真实的布料形变当作 normal 不一致。directional 和逐 GS 两个 3n 实验都受此约束，所以它不是两组差异的唯一来源，但会共同限制 normal 上限，并可能与更准确的局部方向产生不同冲突。

### 6.6 数据本身对 normal/albedo 的约束不足

120 个光位全部位于 `y=-6.172838` 平面，光方向只在有限锥内变化：相对平均方向约 `13.1°–27.7°`，方向矩阵条件数约 `5.69`。同时相机、时间、布料状态和光源一起变化，并不是“同一 surface state 在多盏独立光下”的 photometric stereo。

单观测下 `albedo * max(N·L,0)` 存在强歧义；相机/光/形变同步又让 deformation、visibility 和 view-dependent residual 更难分开。当前模型允许 albedo 和 normal 同时学习，无法仅靠精确一个方向端点消除这种不可辨识性。

### 6.7 `clamp(N·L,0)` 仍有死区

final learned GS 上，局部方向的 `N·L<=0` 比例约 `6.07%`，`N·L<=0.05` 约 `8.24%`；中心方向分别约 `5.81%` 和 `8.00%`。GT-pass 可见前景中，死区也从 `2.04%` 增到 `2.55%`。

更正确的方向会把少量原本被近似方向照亮的点移入截断区；这些点的直接 Lambertian normal/albedo 梯度变为零，缺失的 AREA 角域、间接光和 visibility 又无法补上。因此局部方向更物理，却不保证当前简化优化更容易。

## 7. 损失 preset 的额外审计发现

`lambertian_default` 的描述和 `terms` 列表没有列出 GS normal 与 distortion，但 preset 的 `overrides` 为空；`compute_stage1_loss()` 仍会使用全局默认：

```text
lambda_gs_normal = 0.02
lambda_dist = 1000
```

并在 `iteration > start_normal_reg` 后启用。gradient audit 也确认 `lambertian_normal3` 实验中 `normal` 和 `distortion` 始终存在。

因此正在运行的 `0824-05 ... lambertian_default` 实际只移除了 independent `live/mv` 两项，**没有**移除 GS geometry normal 和 distortion。该实验仍有价值，但不能标为“纯 RGB、无 normal consistency”。这是 preset 元数据/命名的审计问题，不是本次逐 GS 坐标问题。

## 8. 建议的最小实验顺序

### P0：先隔离新增的 shading-position 梯度

新增一个仅用于消融的 forward 选项：方向数值仍实时使用当前 `means3D`，但在光方向分支传入 `means3D.detach()`。这样：

- rasterization 对 geometry 的正常梯度保留；
- 每一步前向仍依据最新 GS 位置更新方向；
- 只切断 `normalize(light_pos-position)` 对 position/deformation 的额外光照梯度。

与当前 0824-04 完全同参比较 RGB、independent normal、GS normal、alpha 时序和 position gradient。若 geometry/alpha 恢复而 independent normal 保持改善，就能确认额外位置梯度是主要退化源之一。

### P1：完成正在运行的 loss 隔离，但准确命名

`0824-05` 应解释为“去掉 independent live/mv，保留 GS normal + distortion”的对照。若还要纯 Lambertian RGB 对照，需要显式设置：

```bash
--lambda_photometric_normal_live 0
--lambda_photometric_normal_mv 0
--lambda_gs_normal 0
--lambda_dist 0
```

不建议在当前训练完成前修改其命令或覆盖输出。

### P2：重新标定局部方向模式的强度 / exposure

本次 test GT-pass 的局部方向全局最优强度约 `5.276`，不是 directional 的 `5.504`；逐帧仍为 `4.42–6.45`。应先在 120 帧同一 mask 口径下为局部方向单独标定强度，再测试固定全局值或有锚定的逐帧 exposure。此项主要处理能量尺度，不会补 visibility/GI。

### P3：构造真正的 AREA 直接光 oracle

需要从 Blender 额外导出每帧 light `matrix_world`/rotation 和 emitter normal；仅有 center/size 不足以确定灯面。随后按单变量顺序测试：

1. 4 或 16 点 AREA 方向积分，不加 visibility；
2. AREA 积分 + 几何项/距离；
3. AREA 积分 + visibility/soft shadow；
4. 最后再加入弱 environment/indirect residual。

不要直接把当前模式切成中心点 `1/r²` 并称为物理 GT；本次 test GT-pass 已表明这种部分替换会破坏更多误差抵消。

### P4：建立真正的 geometry/light oracle

从 Blender 导出 world position/depth、direct diffuse、shadow/visibility 等 pass。在固定 GT geometry、GT albedo、GT normal 下逐项替换，才能回答：

- 光方向本身的 ceiling；
- AREA 与 point center 的差距；
- visibility/indirect 各占多少残差；
- renderer/rasterizer 是否还存在偏差。

对 falling cloth 的多帧 normal 约束，应按 deformation correspondence 或 mesh/barycentric correspondence 对齐，而不是把不同 fid 的 world point 当作静态点。

### P5：改进数据可辨识性与评估

- 同一 cloth state 固定 geometry/camera，渲染多个独立光位；
- 光方向覆盖半球而不是单一平面轨迹；
- 分别报告 foreground RGB、independent normal、GS geometry normal；
- 至少重复两个 seed，避免把单次 0.5–1 dB 差异全部归因于模式；
- 全图 PSNR 继续保留用于复现，但不能代替 foreground/物理指标。

## 9. 最终回答

当前结果“不如理论预期”不是因为逐 GS 光方向在坐标上算错了。恰恰相反，GT-pass 证明它比场景中心方向更准确，并且独立 shading normal 的 GT 误差也实际下降。

真正的问题是：当前只把一个不完整 forward model 中的“方向”改得更物理，却仍使用 learned GS position、AREA 中心、固定强度、无可见性/间接光的 Lambertian；同时这次修改还新增了 RGB 到 GS position 的 shading gradient。在欠建模、normal/geometry 解耦和动态场景静态多视图约束下，优化器会重新分配误差，所以出现“独立 normal 更好、geometry normal 和 RGB 略差”完全合理。

因此该模式应继续保留为有价值的方向消融，但下一步最优先不是再检查 Y/Z 翻转，而是做 `position.detach()` 梯度隔离，并用 Blender position/direct-light pass 建立真正的 AREA/visibility oracle。
