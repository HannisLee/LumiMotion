## 1. 路径约定与选择原则

| 目录 | 角色 | 能否直接作为 `--source_path` |
| --- | --- | --- |
| `data/LH-data/danamic/<数据集>` | 动态数据原始导出；目录名 `danamic` 是历史拼写，不能自行改名 | 否；先使用对应 `transfer-dynamic` 数据 |
| `data/LH-data/static/<数据集>` | 静态数据原始导出 | 否；先使用对应 `transfer-static` 数据 |
| `data/LH-data/transfer-dynamic/<数据集>` | 已转换的动态 Blender loader 数据 | 是 |
| `data/LH-data/transfer-static/<数据集>` | 已转换的静态 Blender loader 数据 | 是 |

表中 `data/LH-data` 为历史相对路径。本次 V4 数据使用下文 `/home/lihan/data/LH-data` 的绝对路径；原版项目并没有 `data/LH-data` 链接。两个新增动态集的原始文件实际在 `static/` 下，保留原始目录不改名，转换后按动态属性写入 `transfer-dynamic/`。

转换后的训练目录应包含 `transforms_train.json`、`transforms_test.json`、`images/` 与 `dataset_manifest.json`。训练时固定使用：

```bash
--source_path data/LH-data/transfer-<dynamic|static>/<数据集> \
--train_light_folder images \
--is_blender \
--eval
```

除非明确核对过 `<source_path>/rgba/`，不要在转换目录中保留它：现有 loader 会优先读取 `rgba/`，从而覆盖 `--train_light_folder images` 的预期。

## 3. 所有训练集共用的模态与 Alpha 约束

原始 LH 数据通常包含 RGB 图像、`albedo/`、`normal_exr/`、`camera.json`、`lights.json`、`object_pose.json` 以及初始点云。转换脚本生成 Blender 训练格式时：

```text
原始 albedo PNG 的 Alpha
        ↓
转换集 images/*.png（RGBA，训练实际读取）
        ↓
Camera.gt_alpha_mask 与 Alpha loss
```

因此，Alpha 不是可选的附属文件，而是前景/背景分离的监督信号。对全部数据集均应遵循：

- 训练命令显式传入 `--gt_alpha_mask_as_scene_mask`。
- `images/*.png` 必须有真实第 4 通道：背景为 0、前景为 255，软边保持 `0 < alpha < 255`。
- 不要把 RGB、原始 `image/`、`albedo/` 和转换后 `images/` 混合使用，也不要转换后再次手工乘 Alpha。
- 长训练前读取 `dataset_manifest.json`，确认 `summary.mask_source == "albedo-alpha"`、无全 0 Alpha 帧，并抽查首/中/尾帧的 RGB 与 Alpha 对齐。
- 训练、渲染和恢复 checkpoint 时的 `--white_background` 必须保持一致；白/黑背景不一致会造成轮廓暗边及错误的 RGB/Alpha 损失。

`normal_exr/` 是世界坐标系 GT normal，只用于离线评估或明确标注的 oracle 实验；普通 Lambertian Stage 1 不应把它作为训练监督。

| 数据集 | 建议光照元数据 | `photometric_light_mode` | 关键限制 |
| --- | --- | --- | --- |
| CV3 | `data/LH-data/danamic/only_clothV3/lights.json` | `gt_directional` | 方向光只使用方向，不使用灯距和 `1/r²`。 |
| CV3L | `data/LH-data/danamic/only_clothV3_lambertian/lights.json` | `gt_directional` | 必须重新标定 irradiance；不得复用 CV3 的 5.5043499。 |
| TDL | `data/LH-data/transfer-static/only_clothV3_true_direction_light/lights_compat_point_position.json` | `gt_directional` | **只能**使用转换产生的兼容灯位 JSON；不能用 `gt_point`。 |
| 其余数据集 | 对应原始 `lights.json`，经格式核验后使用 | 按实验目标决定 | 启动长训练前必须确认字段语义、坐标系与强度标定。 |

### TDL：真实方向光的兼容方式

TDL 原始 `lights.json` 存储的是 SUN 光的 `light_dir_world`，其语义为从表面指向光源的单位向量 `D`。现有管线的 `gt_directional` 从点光位置构造光线，并在 Lambertian 前将其反向为表面到光源方向。

为不修改主训练管线，转换脚本在每帧相机中心 `C` 附近构造虚拟点光位置：

```text
P = C + rD,  r = 10
```

并写入转换集的 `lights_compat_point_position.json`。在原有 `gt_directional` 路径中，这与 GT 方向 `D` 等价：只保留方向，忽略距离。该转换已经数值验证；float64 最大方向误差为 `2.96e-6°`，沿用管线 float32 的最大误差为 `0.01978234°`。

禁止将此 JSON 配合 `gt_point` 使用，因为 `gt_point` 会引入并不属于 SUN 光的距离衰减 `1/r²`。TDL 的光强仍需独立标定，不能根据“方向等价”推断强度等价。

对应转换实现为：`LIHAN/scripts/prepare_true_direction_light_dataset.py`；转换与验证记录见 `LIHAN/DOC/修改/修改/0829-01-真实方向光兼容灯位数据转换.md`。

## 5. 训练前的数据集选择清单

1. 使用动态布料主基准时，选择 CV3；若对照 Lambertian 数据，必须同时记录 CV3L，并确保除数据/必要强度外的配置可比。
2. 使用真实 SUN 方向光时，选择 TDL 转换集和第 4 节指定的兼容 JSON，固定 `--photometric_light_mode gt_directional`。
3. `--source_path` 一律指向 `transfer-*` 目录；光照元数据仍按表中路径单独传给 `--photometric_gt_lights_path`。
4. 确认 120 帧、train/test 无重叠、各模态帧号一致，且 `dataset_manifest.json` 的 Alpha 统计正常。
5. 记录数据集别称、完整 source/light 路径、背景设置、光照模式和强度到实验 `README.md`；不要只写“CV3”或“方向光”。

## 6. 维护规则

- 新增原始数据时：先补充本清单的原始路径、帧数、静态/动态属性与光照语义。
- 转换完成并通过 Alpha/文件名检查后：补充转换路径、`dataset_manifest.json` 状态和训练可用性。
- 改变灯光字段、坐标系、Alpha 来源、相机定义或点云格式时：不得沿用旧条目的“可训练”结论；需要新增转换/验证说明与训练文档。
- 本文只维护数据资产与使用约束；具体实验结果、checkpoint 和验收结论应记录在 `DOC/训练/` 与对应 `output/<实验>/README.md`。
