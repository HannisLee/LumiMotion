# Albedo、法线与 Roughness MAE 使用指导

更新日期：2026-10-08。统一评测 **GT 定义的整个前景**，不按材质、颜色或物体类别拆分。换数据集时，只需更换模型、GT 和输出路径，评测帧从数据集划分读取。

## 指标口径

| 指标 | 真值与计算 | 主要结果字段 |
| --- | --- | --- |
| Albedo MAE | GT albedo RGBA PNG；在线性 RGB 中平均三个通道的绝对误差 | `summaries.raw.foreground.mae_linear` |
| Normal MAE | GT 世界坐标单位法线 EXR；预测与 GT 的平均夹角，单位为度 | `summary.foreground.normal_metrics.gs_render.mae_pixel_mean_deg` |
| Roughness MAE | GT 原始粗糙度标量 r；预测与 GT 的绝对误差 | `summaries.foreground.mae` |

默认使用测试帧。Albedo、roughness 的前景为 GT alpha≥0.99 后内缩2像素；法线主指标使用 GT alpha≥0.5，并另存前景内部区域诊断。三项均按有效像素数量汇总，不按材质等权。

**MAE 要与覆盖率一起看。** 法线与 roughness 只对有效预测计 MAE，漏检计入覆盖率分母；albedo 延续现有协议，在全部 GT 内部前景评分，完全漏检处的预测记零。三个数值的单位、漏检处理不同，不能直接互相比较。

`--split all` 指训练帧和测试帧全部评测，仍然只评分前景，不表示把背景加入 MAE。

## 运行命令

在仓库根目录执行，先用 `hostname` 确认服务器并使用对应 Conda 环境。以下为 venus 示例；路径使用实际绝对路径，每次选择新的输出目录。

```bash
PYTHON=/home/lihan/miniconda3/envs/lumimotion/bin/python
MODEL=/绝对路径/model_mlp
GT=/绝对路径/原始数据集
OUT=/绝对路径/本仓库/output/日期-序号-数据集-MAE
```

**Albedo：**需要 `$GT/albedo/` 下的 RGBA PNG，文件名末尾为原始帧号。

```bash
"$PYTHON" -m scripts.eval_albedo_gt \
  --model_path "$MODEL" --iterations 55000 \
  --gt_albedo_dir "$GT/albedo" --split test \
  --output_path "$OUT/albedo" --save_float
```

PNG 没有颜色空间标记时，先确认它确为 sRGB 编码，再加 `--assume_srgb`。主指标使用 raw，尺度校准仅用于诊断。

**法线：**需要 `$GT/normal_exr/normal_帧号.exr` 及 `$GT/camera.json`，相机应与训练数据对应。

```bash
"$PYTHON" -m scripts.eval_geometry_gt \
  --model_path "$MODEL" --load_iter 55000 \
  --gt_root "$GT" --split test --resolution 2 \
  --output_dir "$OUT/normal" --save_arrays
```

`--resolution 2` 表示原始分辨率除以2，按实际训练分辨率调整。默认主指标是 GS Render Normal MAE；Depth Normal 另存，Mesh Normal 需要通过 `--pred_mesh_manifest` 提供模型提取的网格。

**Roughness：**仅适用于原版 PBR Stage2。准备逐帧真值图，帧号从文件名末尾读取：

- 推荐 NPZ：包含 `roughness` 和 `alpha` 两个 HW 或 1HW 数组，取值在 [0,1]；r 是未乘 alpha、未做 gamma 转换的原始参数。可附加 `time` 与 Blender 坐标系的 `camera_to_world` 供对齐检查。
- 或原始浮点 RGBA EXR：Blender 输出的 RGB=r×alpha，评测会先除 alpha；专用 `roughness` 通道则直接存 r。不要使用展示用 PNG。

```bash
"$PYTHON" -m scripts.eval_roughness_gt \
  --model_path "$MODEL" --iteration 55000 \
  --gt_roughness_dir "$GT/roughness" --split test \
  --output_path "$OUT/roughness"
```

若源数据未导出 roughness，可用 `scripts/export_roughness_gt.py` 从对应 Blender 场景生成。它支持直接 Principled BSDF 的常量或节点驱动 Roughness 输入，不依赖材质名称；用对应 split 的 transforms 核对相机和时间：

```bash
/绝对路径/blender --background --factory-startup --disable-autoexec \
  --python-exit-code 1 /绝对路径/场景.blend \
  --python scripts/export_roughness_gt.py -- \
  --transforms /绝对路径/训练数据/transforms_test.json \
  --resolution 2 --output_dir "$OUT/gt_roughness"
```

生成后将 `--gt_roughness_dir` 指向该目录。透明或混合 BSDF 的定义需要数据生成端提供明确的 roughness 真值图，当前导出器会拒绝处理。

## 查看结果

每个入口保存 `metrics.json`、逐帧表及代表图。Albedo 的结果位于 `iteration_55000/`；法线和 roughness 位于各自输出目录。优先看上表的全前景 MAE、覆盖率及 GT/预测对照图。

Roughness 浮点结果可独立复算：

```bash
"$PYTHON" -m scripts.verify_roughness_eval "$OUT/roughness"
```

新增数据只需保证同帧、同相机、同时间、同坐标定义。输出会保留实际帧号及分辨率，不要求固定材质种类或固定帧数。
