# 训练集加载要求

本文用于训练前检查 Blender/`transforms` 格式数据，重点防止以下两类问题：

1. Alpha 通道缺失、反向、错帧或前景/背景含义不一致。
2. `transforms_*.json` 中的文件名与磁盘文件的前缀、数字后缀或扩展名不一致。

这两类问题有时不会在数据加载阶段立即报错，可能表现为训练不收敛、主体消失、Alpha loss 异常或结果带黑边。因此，训练前必须完成本文检查。

## 1. 训练入口与目录结构

当 `source_path` 下存在 `transforms_train.json` 时，代码会按 Blender 数据集加载。最小目录结构如下：

```text
<dataset>/
├── transforms_train.json
├── transforms_test.json       # 建议保留，用于 eval
├── images/                    # 由 --train_light_folder 指定
│   ├── frame_0001.png
│   ├── frame_0002.png
│   └── ...
└── dataset_manifest.json      # 使用 prepare_lh_dynamic.py 时生成
```

训练命令中的 `--train_light_folder` 必须与实际目录一致。例如上面的结构必须使用：

```bash
--source_path <dataset> --train_light_folder images --is_blender --eval
```

不能把 `--source_path` 指向 `images/` 子目录，也不能把 `--train_light_folder` 写成源数据目录名。默认值是 `chapel_day_4k_32x16_rot0`，如果数据没有这个目录，必须显式传参。

## 2. Alpha 通道硬性要求

### 2.1 Alpha 必须存在于训练图片的第 4 通道

训练加载器会读取：

```text
<source_path>/<train_light_folder>/<file_path>
```

然后将图片转成 RGBA。RGB 图片即使能够被 PIL 打开，也会被自动补成全 255 Alpha；这不会报错，但会把整张图误当成完整前景。因此，不能只检查“图片能否打开”，必须检查源文件确实包含有效 Alpha。

每帧应满足：

- 图片为 PNG/RGBA，或使用明确包含透明度信息的格式。
- Alpha 与 RGB 的宽高完全相同。
- Alpha 语义统一：`0` 是背景，`255` 是前景，`0 < alpha < 255` 是软边。
- 所有帧使用同一种 Alpha 语义，不能某些帧反向为 `0=前景、255=背景`。
- 不能出现全 0 Alpha；这会使训练目标没有有效前景。
- 对正常存在背景的动态物体，不能出现某些帧全 255 而其他帧有明显背景，除非这是已确认的全画幅前景数据。
- 不要把独立 mask 放在别的目录后就认为训练会自动读取；Blender loader 只使用训练图片自身的 Alpha 通道。

### 2.2 Alpha 与训练参数必须一致

使用 Alpha 监督时，Stage 1/Stage 2 命令应明确包含：

```bash
--gt_alpha_mask_as_scene_mask
```

该参数会让训练使用图片 Alpha 计算 Alpha loss。若数据没有可靠 Alpha，不要只靠这个参数“补救”，应先修复数据或关闭 Alpha 监督并记录原因。

背景配置也必须和数据保持一致：

- `--white_background`：训练器按白色背景合成。
- 不传 `--white_background`：训练器按黑色背景合成。

训练、Stage 1 渲染和 Stage 2 加载时的 `--white_background` 应保持一致。否则 RGB 目标和 Alpha 轮廓可能不一致，出现边缘发黑、主体变淡或背景参与损失的问题。

### 2.3 软 Alpha 的额外注意事项

Alpha 边缘应保持连续，不能出现明显的整圈黑边、锯齿、偏移或 RGB 与 Alpha 不重合。不要在转换脚本输出之后再次手工乘 Alpha 或重复抠图；否则软边可能被二次预乘，训练图像会变暗。

使用 `scripts/prepare_lh_dynamic.py` 时，必须使用它生成的 `images/` 作为训练目录，不要把源 `image/`、`albedo/` 和生成后的 `images/` 混用。该脚本使用 `albedo/*.png` 的 Alpha 生成训练 RGBA，并在 `dataset_manifest.json` 中记录 mask 统计。

转换后至少检查：

```text
dataset_manifest.json
├── summary.mask_source == "albedo-alpha"
├── mask.nonzero_pixels       # 每帧非零前景像素数
└── mask.soft_pixels          # 每帧软 Alpha 像素数
```

`nonzero_pixels` 不应有 0；最小值和最大值也不应出现无法解释的突变。`soft_pixels` 可以为 0（硬 mask 合法），但如果原始数据预期有软边而这里全部为 0，应暂停训练并检查 Alpha 是否被量化或丢失。

## 3. 文件名、前缀、数字后缀与扩展名

### 3.1 JSON 与磁盘文件必须完全对应

`transforms_train.json` / `transforms_test.json` 中每个 frame 的 `file_path` 必须对应真实文件。例如：

```json
{
  "file_path": "frame_0001.png",
  "time": 0.0,
  "transform_matrix": [[...], [...], [...], [...]]
}
```

磁盘上必须存在：

```text
<source_path>/<train_light_folder>/frame_0001.png
```

以下情况都视为错误：

- JSON 写的是 `frame_0001.png`，实际是 `rgba_0001.png`。
- JSON 写的是 `frame_0001.png`，实际是 `frame_0001.jpg`。
- 数字后缀不一致，例如 `frame_1.png` 对 `frame_0001.png`。
- 前缀不一致，例如 `timestep_0001.png` 对 `frame_0001.png`。
- 大小写或扩展名不一致，例如 `.PNG`、`.JPG`。
- 同一个数字帧在目录中有两个文件，导致来源不确定。

当前 loader 会按文件名最后的下划线数字排序，因此推荐统一使用：

```text
frame_0001.png
frame_0002.png
...
```

也就是说，文件名 stem 应以 `_数字` 结尾。不要使用无法解析的名称，例如 `frame_a.png` 或 `frame_0001_view.png`。

### 3.2 `rgba/` 目录会覆盖 `train_light_folder`

如果 `<source_path>/rgba/` 存在，当前 loader 会优先读取：

```text
<source_path>/rgba/<file_path 的 basename>
```

这意味着即使命令指定了 `--train_light_folder images`，一个遗留的 `rgba/` 目录也可能被实际加载。使用前必须确认 `rgba/` 是有意使用且其中的文件与 JSON 完全一致；否则应将其改名或移出数据集目录，并保留可恢复副本。

## 4. 帧号与多模态对齐

对于 LH Dynamic 原始数据，以下来源必须拥有完全相同的帧号集合：

```text
image/
albedo/
normal_exr/
camera.json
lights.json
object_pose.json
```

不能只比较文件数量，必须比较文件名末尾数字得到的帧号。禁止缺帧、重复帧和错帧配对，例如：

```text
image/frame_0012.png   对   albedo/frame_0013.png
```

推荐统一使用转换脚本完成检查和生成：

```bash
python scripts/prepare_lh_dynamic.py \
  data/LH-data/danamic/only_clothV2 \
  data/LH-data/transfer-dynamic/only_clothV2 \
  --test-stride 8 \
  --camera-extent 1.0
```

注意：输出目录必须为空。脚本会检查各模态帧号集合、相机元数据和 RGB/Albedo 分辨率；如果报 `Frame mismatch`、`Unexpected image size` 或 `Required ... missing`，禁止继续训练。

## 5. transforms 与相机字段

每个 frame 至少应包含：

- `file_path`：相对数据集根目录、相对于 `train_light_folder` 的图片路径。
- `transform_matrix`：有限的 4×4 camera-to-world 矩阵。
- `camera_angle_x` / `camera_angle_y`，或有效的 `fl_x` / `fl_y`。
- `time`：建议显式提供，并且 train/test 使用同一套时间归一化规则。

所有训练帧的图片都应具有相同的宽高。相机内参、外参和图片尺寸必须对应同一帧；不要只复制第一帧的相机矩阵到全部帧，除非数据确实是固定相机。

## 6. 训练前一票否决清单

以下任意一项不满足，都不要启动长训练：

- [ ] `transforms_train.json` 存在且能被 JSON 解析。
- [ ] `--source_path` 与 `--train_light_folder` 组合后能找到所有训练图片。
- [ ] JSON 中每个 `file_path` 与真实文件名、前缀、数字后缀、扩展名完全一致。
- [ ] 每帧源图片都有明确 Alpha，不是被 loader 自动补出的全 255 Alpha。
- [ ] Alpha 方向统一，背景为 0，前景为 1；没有全 0 帧。
- [ ] RGB、Alpha 尺寸一致，Alpha 轮廓与 RGB 主体对齐。
- [ ] train/test 的帧号不重复，且 test 不为空（需要 eval 时）。
- [ ] LH 数据的 image、albedo、normal、camera、light、pose 帧号集合一致。
- [ ] 没有未核对的 `<source_path>/rgba/` 覆盖目录。
- [ ] 训练与渲染的 `--is_blender`、`--train_light_folder`、`--resolution` 和 `--white_background` 配置一致。
- [ ] 已打开至少一张开头、中间、结尾帧，目检 RGB 与 Alpha，而不只是检查文件数量。

## 7. 最小抽查命令

下面命令用于抽查训练集图片是否存在 Alpha、尺寸是否一致以及 Alpha 覆盖率是否合理。将 `DATASET` 和 `TRAIN_DIR` 改成实际路径：

```bash
DATASET=/path/to/dataset
TRAIN_DIR="$DATASET/images"

python - "$DATASET" "$TRAIN_DIR" <<'PY'
import json
import sys
from pathlib import Path
from PIL import Image

dataset = Path(sys.argv[1])
train_dir = Path(sys.argv[2])
with (dataset / "transforms_train.json").open(encoding="utf-8") as f:
    frames = json.load(f)["frames"]

sizes = set()
errors = []
for frame in frames:
    rel = frame["file_path"]
    path = train_dir / rel
    if not path.is_file():
        errors.append(f"missing: {path}")
        continue
    with Image.open(path) as image:
        has_alpha = "A" in image.getbands() or "transparency" in image.info
        rgba = image.convert("RGBA")
        alpha = rgba.getchannel("A")
        lo, hi = alpha.getextrema()
        alpha_values = list(alpha.getdata())
        nonzero = sum(value > 0 for value in alpha_values)
        soft = sum(0 < value < 255 for value in alpha_values)
        sizes.add(rgba.size)
        if not has_alpha:
            errors.append(f"no explicit alpha: {path}")
        if hi == 0:
            errors.append(f"all-zero alpha: {path}")
        coverage = nonzero / (rgba.size[0] * rgba.size[1])
        print(
            f"{path.name}: size={rgba.size}, alpha={lo}..{hi}, "
            f"coverage={coverage:.2%}, soft={soft}"
        )

if len(sizes) > 1:
    errors.append(f"inconsistent image sizes: {sorted(sizes)}")
if errors:
    print("FAILED")
    print("\n".join(errors))
    raise SystemExit(1)
print(f"PASS: {len(frames)} frames, size={next(iter(sizes))}")
PY
```

## 8. 代码依据

- 数据格式转换与帧号/尺寸检查：`scripts/prepare_lh_dynamic.py`
- Blender transforms 加载与 Alpha 读取：`scene/dataset_readers.py`
- 图片缩放、Alpha mask 传入 Camera：`utils/camera_utils.py`
- Stage 1 损失组装（RGB/Alpha/几何正则等）：`scripts/loss.py`，由 `scripts/train_stage1.py` 调用；命名组合用 `--loss_preset` 选择（2026-08-23 起）

如需修改 Alpha 处理、文件名解析或数据转换逻辑，必须同时更新本文，并先做短时冒烟训练和 RGB/Alpha 可视化检查，再进行正式训练。
