## 2. 代码改动

### 2.1 新增 `scripts/loss.py`

- `Stage1LossResult`：返回总 loss、`audit_terms`（键名与顺序保持历史约定，供梯度审计/日志复用）、`pbr_terms`、`l1`（供 training_report）、`light_smooth`（供 `log_photometric_stats`）、`gt_normal_oracle`（GT-normal oracle 日志素材）。
- `compute_stage1_loss(tr, viewpoint_cam, render_pkg_re, image, gt_image, d_xyz, ...)`：按原 `train_step` 的**完全相同顺序**组装全部损失项：
  - RGB：SH 路径 L1+DSSIM 加权 / PBR 路径 mse+前景 L1+前景 DSSIM+log-linear；
  - 几何法线自一致 + 深度畸变（`start_normal_reg` 门控，PBR 关闭）；
  - GT-normal 监督（`lambda_photometric_gt_normal`）、独立法线信任域先验（`lambda_photometric_normal_init`）；
  - 独立法线一致性 `photometric_normal_live` / `photometric_normal_mv`（连同 `render_world_normal_map()`、`normal_consistency_terms()` 一并从 Trainer 搬入，原方法名 `normal_consistency_losses()`）；
  - 光源平滑（调 `renderer.light_smoothness_loss()`）、PBR 六项正则（调 `renderer.regularization_losses()`）；
  - alpha/mask 损失（GT mask 与 simulated-mask 两分支）、`d_xyz`/`d_color` 正则、二值化 separation。
- 渲染器内部损失方法（`scene/photometric_*.py` 的 `light_smoothness_loss()` / `regularization_losses()`）按约定**不搬迁**，仅被调用；`train_stage2.py` 不在本次范围。
- 预设注册表 `LOSS_PRESETS`（`LossPreset`：描述/兼容 render_mode/覆盖参数/损失项清单）：

| 预设名 | 兼容 render_mode | 覆盖的参数（未显式传时才生效） |
| --- | --- | --- |
| `sh_baseline` | original_sh | 无（默认即基线组合） |
| `lambertian_default` | photometric_lambertian | 无 |
| `lambertian_normal3` | photometric_lambertian | `lambda_photometric_normal_live=0.01`、`lambda_photometric_normal_mv=0.02`（即 0823-01 三法线一致性组合） |
| `pbr_default` | photometric_perlight_pbr | 无 |
| `n0_gt_normal_oracle` | photometric_lambertian | `photometric_rgb_loss_weight=0.0`、`lambda_photometric_gt_normal=1.0` |

- `apply_loss_preset(args, argv)`：`auto`（默认）不做任何修改；命名预设只覆盖命令行**未显式给出**的参数（按 argv 扫描判定），显式 CLI 永远优先；预设与 `--render_mode` 不兼容时报错并列出可用预设。

### 2.2 `scripts/train_stage1.py`

- `train_step()` 中约 240 行内联损失代码替换为一次 `compute_stage1_loss(...)` 调用；backward、EMA、TensorBoard 写入、`audit_loss_gradients`、`log_gt_normal_oracle`、`log_photometric_stats` 行为不变。
- 移除已搬迁的 `Trainer.render_world_normal_map()`、`Trainer.normal_consistency_losses()`；`gt_normal_for_camera()`（数据缓存）保留在 Trainer，由 loss.py 通过 trainer 上下文调用。
- 清理不再使用的导入（`ssim`、`alpha_normalized_normal_map`、`masked_normal_cosine_loss`、`depths_to_points`、`srgb_to_linear`）。
- `main()` 在 `parse_args` 后调用 `apply_loss_preset(args)`。

### 2.3 `arguments/__init__.py`

- `OptimizationParams` 新增 `self.loss_preset = "auto"`（3 行，含注释），随 `cfg_args` 一并落盘可追溯。

### 2.4 兼容性说明

- `--loss_preset` 缺省 `auto`：不写任何参数，全部行为由既有 `lambda_*`/开关决定，**逐位等价**于重构前。
- 所有既有命令行、`cfg_args` 与恢复训练流程不受影响；新增参数有默认值，旧命令无需改动。

## 4. 验证

全量套件：`python -m unittest discover -s tests` → **51 项全部通过**（重构前后各跑一次）。

### 4.2 数值等价冒烟（`output/smoke_test/`，CV3s，300 iter，命令见各目录 `run.sh`）

| 目录 | 说明 |
| --- | --- |
| `0823-01-CV3s_loss_refactor_pre_{lambertian,sh}` | 重构前基线（Lambertian 分支 + SH 基线分支，门控前移覆盖更多损失项） |
| `0823-01-CV3s_loss_refactor_post_{lambertian,sh}` | 重构后同命令重跑 |
| `0823-01-CV3s_loss_refactor_post_lambertian_b` | **对照**：与 post_lambertian 完全相同的代码再跑一次 |
| `0823-01-CV3s_loss_refactor_final_{lambertian,sh}` | 最终提交文件状态的收尾冒烟 |

对比 `gradient_audit.csv` 逐项 `loss_value`：

- iteration 1（首个审计点）：两分支均 **48/48 / 36/36 逐位相等**；
- 早期迭代（≤50）相对差：重构前-后 max `6.9e-5` / avg `1.2e-5`，而**同一份重构代码两次运行**（对照）max `4.6e-5` / avg `8.5e-6` —— 同量级；
- 其后差异随训练轨迹混沌放大（≤0.9），与对照运行表现完全一致。

结论：差异为 CUDA 固有的运行间噪声（光栅化反向原子操作/卷积算法选择等），**重构未引入任何数值变化**；若损失公式被改动，iteration 1 即会出现系统性偏差（实际逐位相等）。
