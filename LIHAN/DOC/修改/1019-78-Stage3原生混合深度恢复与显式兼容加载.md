# Stage3原生混合深度恢复与显式兼容加载

2026-10-19，ushas／lumimotion-ushas。发现首轮Stage3把Stage2的Expected法线正则设置沿用到了PBR追踪点，偏离原生PBR默认。该问题不影响Stage2的共享SH＋DL、几何资产或已完成8100步记录。

## 原因与TRAIN核验

原生 `arguments.PipelineParams.depth_ratio=1`，`render_ir`内部 `min(.5, depth_ratio)`，即Expected／Median各50%。Stage2为Expected深度法线一致性设置0是有意的，但首轮Stage3未恢复原生默认，实际使用了纯Expected追踪点。原生渲染流程必须明确记录这个接口，不能将纯Expected默认称为未修改的原生PBR。

`scripts/audit_three_stage_pbr_depth.py`在固定S20@8100转换状态、相同256积分、同材质／几何／环境、无更新的TRAIN 1／75／149上比较0与原生1。追踪点平均移动.003125／.003546／.003494世界单位，p95约.005065／.010157／.010700；Alpha最大差0。预测上向区域可见度由.7072／.5991／.5835变为.7441／.6658／.6546，线性RGB差约.0224／.0401／.0392。不是GT或几何精度改善；仅证明接口差异足以改变遮挡和外观。

首次诊断v1因CPU Alpha与CUDA掩膜设备不一致退出，已有图片与失败现场保留；修复后新建v2完成核验。准备终止时核验发现A30／A31均已完成4050步、原训练进程句柄缺失，因此未发送终止信号，也不重启原目录；完整终点／统计／日志保留，并另行标记原生接口验收FAILED。退出码0及旧保存重载工程PASS不代表原生接口符合要求；两者不用于宣称原生基线或残差改善。

## 修复实现

- `scene/three_stage_native_pbr.py`新增NativePBRModel，仅用于Stage3，显式保存native_half和depth_ratio=1。保留原生render_ir、材质、环境、BRDF与可见度；不修改实际前向库的源代码。统一load_three_stage_model按记录加载旧Expected或新原生混合深度，未知模式报错；不重解释旧模型，不回退GT光。
- `scripts/train_three_stage.py`允许显式模型类／入口／附加源码绑定；默认行为保留。新入口 `scripts/train_three_stage_native_pbr.py`使用原生混合深度模型，真实入口与新类源码SHA进入记录。
- `scripts/run_three_stage_job.py`显式选择已登记入口，默认仍可复现旧实验。新正式与工程使用native入口和新快照，禁止覆盖旧目录。
- 独立加载审计、TRAIN诊断、隔离评测均按保存模式分派。诊断内部一致性另取纯Expected几何副本，避免把混合深度法线冒充Expected法线。评测RGB对应深度检查按原生实际.5混合进行；Expected／Median／Mesh三类正式几何度量仍各自独立。
- 评测生成的GPU子进程显式使用评测器所在冻结代码目录，避免工作树后续编辑影响已冻结评测。旧评测若因代码SHA保护中止，保留结果并以新目录／冻结源重新运行，不关闭来源保护。

修复不更改S20／S21几何、灯向或统计，不据GT改参数；新Stage3全部4050预算及其他超参按训练计划1019-25预登记。
