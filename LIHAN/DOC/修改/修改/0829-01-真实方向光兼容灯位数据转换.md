# 真实方向光兼容灯位与数据集转换

日期：2026-08-29
服务器/环境：garuda / `lumimotion-garuda`

## 目标

新增原始数据集 `data/LH-data/static/only_clothV3_true_direction_light` 使用 Blender SUN 的真实方向光字段 `light_dir_world`。现有 Stage 1 的 `gt_directional` 初始化接口只读取 `light_pos_world`，本次不修改训练、渲染或加载代码，而是在转换数据集中生成可被旧接口读取的虚拟灯位。

## 新脚本

脚本：[LIHAN/scripts/prepare_true_direction_light_dataset.py](../../LIHAN/scripts/prepare_true_direction_light_dataset.py)

脚本复用既有 `scripts/prepare_lh_dynamic.py` 生成 RGBA、`transforms_train.json`、`transforms_test.json` 与 `dataset_manifest.json`，并额外：

- 将原始 `Point3D.ply` 的 5000 个 xyz 点原样写入 `points3d.ply`；补零法线和灰色 RGB `(128,128,128)`，以满足 `fetchPly()` 的字段要求；
- 保留原始仅 xyz 点云为 `points3d_xyz_only.ply.bak`；
- 生成 `lights_compat_point_position.json`，不修改原始的 SUN `lights.json`；
- 写入 `conversion_validation.json`，记录帧、点云和方向验收结果。

## 方向等价关系

原始 `light_dir_world` 的语义为 surface-to-light 向量 `D`。旧 `gt_directional` 管线对每帧灯位 `P` 和初始化点云均值 `C` 计算：

```text
raw_ray = normalize(C - P)             # light-to-surface
surface_to_light = -raw_ray            # 参与 N·L
```

因此脚本使用固定虚拟距离 `r=10.0` 构造：

```text
P = C + r * normalize(D)
```

这样旧管线恢复的 `surface_to_light` 与 GT `D` 相同。虚拟距离在 `gt_directional` 模式中不会参与衰减或着色，只用于形成该方向；此兼容 JSON **不得**传给 `gt_point`，否则会引入不属于方向光的平方反比距离衰减。

## 执行命令

```bash
conda run --no-capture-output -n lumimotion-garuda \
python LIHAN/scripts/prepare_true_direction_light_dataset.py \
  data/LH-data/static/only_clothV3_true_direction_light \
  data/LH-data/transfer-static/only_clothV3_true_direction_light \
  --test-stride 8 --camera-extent 1.0 --virtual-light-distance 10.0
```

后续训练保持原有 `--photometric_light_mode gt_directional`，仅将灯光路径改为：

```text
data/LH-data/transfer-static/only_clothV3_true_direction_light/lights_compat_point_position.json
```

## 本次验收

- 数据集：120 帧，训练 105 帧、测试 15 帧，图像均为 1280×720 RGBA；
- Alpha 抽查帧 0001/0060/0120 均为 `0..255`，软边像素分别为 4750/4906/4592；
- 点云：5000 点，转换前后 xyz 最大绝对差为 `0.0`；
- 灯光：120 个帧键与原始 `lights.json` 完全一致；按旧管线公式回算的 float64 最大方向角误差为 `2.96e-6°`；按 float32 旧运行路径模拟的最大误差为 `0.01978234°`，低于脚本阈值 `0.03°`；
- 结论：**PASS**。原始数据和既有训练/渲染数据管线均未改动。
