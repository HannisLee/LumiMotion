# 共享资料本地白名单全分支同步

日期：2026-10-30。服务器：ushas。执行环境：`lumimotion-ushas`。

本轮新增 `LIHAN/scripts/sync_shared_local_whitelist.py`，用于在大量既有工作区改动存在时，仅将明确列出的本轮共享文件同步至所有本地分支。原 `goal_sync_shared.py` 即使只检查也会先联网拉取，正式执行还会推送远端，不适用于本轮仅本地同步要求；原脚本保持原样。

## 使用方法

先等待本轮训练、验收与文档更新全部完成。将最终完整清单写入 `output` 内的 JSON 文件，清单只包含本轮明确授权文件，不得使用目录或通配符：

```json
{"paths": ["LIHAN/scripts/sync_shared_local_whitelist.py", "LIHAN/DOC/修改/1030-02-共享资料本地白名单全分支同步.md"]}
```

上述清单只是本脚本与说明文档的最小示例；本轮其他训练计划、修改文档与目标文档需由主执行者最终汇总。

默认只读检查：

```bash
/home/han.li/miniconda3/envs/lumimotion-ushas/bin/python LIHAN/scripts/sync_shared_local_whitelist.py \
  --manifest output/本轮同步清单.json \
  --control output/1030-01-共享同步状态
```

最终文件冻结后执行：

```bash
/home/han.li/miniconda3/envs/lumimotion-ushas/bin/python LIHAN/scripts/sync_shared_local_whitelist.py \
  --manifest output/本轮同步清单.json \
  --control output/1030-01-共享同步状态 \
  --message '1030：本轮共享资料本地全分支同步' --apply
```

脚本没有联网、拉取或推送步骤。默认检查也不会创建 Git 对象、提交或更新引用。正式执行会为每个需要更新的本地分支创建提交，并以旧提交编号进行一次原子引用事务；无需切换分支或创建工作树。Git 分支引用必须指向提交，因此将文件持久化到分支历史需要创建本地提交。

## 保护规则

- 仅接受 `LIHAN/` 内或 `LIHAN.md` 的普通文件，拒绝目录、符号链接、路径越界、重复清单、游离分支与冲突索引。
- 要求所有本地分支原有共享树完全一致，且没有其他分支被工作树占用；有分歧时停止，不覆盖分支独立内容。
- 临时索引从当前分支已提交树创建，仅写入清单文件的快照；既有用户修改、删除和未跟踪文件不会进入提交。
- 对每个候选提交检查差异路径严格包含于清单；其他项目实现文件始终沿用各分支原有树。
- 正常索引仅刷新清单文件，保留其他已暂存内容。检查失败时以旧编号事务回退引用，并仅恢复清单对应索引项。
- 对清单之外的用户文件只读取 Git 状态和文件元数据，不读取文件内容；执行前后检查这些状态及非清单索引项一致。状态目录中的脚本自身产物不纳入用户文件保护比较。
- 同步期间应暂停对清单文件的写入。脚本会检查准备期间文件快照是否变化；如果其他进程同步改动引用，事务会拒绝执行。
- 每次执行使用带微秒时间戳的 JSON 保存父提交、候选提交、共享树和最终状态；不覆盖历史记录。重复执行相同内容不会创建额外提交。

清单本身决定授权边界，操作者必须检查其中没有此前遗留的用户修改文件。脚本不会替操作者判断一个同名文件中的修改属于哪次会话。

## 验证结果

使用 `lumimotion-ushas` 的 Python 在独立临时仓库实际执行：两个本地分支同步后的共享树一致；用户原有暂存、未暂存、删除与未跟踪状态全部保留；重复执行未产生额外提交。首次测试发现未忽略的状态目录会触发保护检查，已修正为仅排除指定状态目录下的脚本产物，随后复测通过。

本仓库当前只执行只读检查，不更新任何分支引用、不创建同步提交、不推送远端。检查时本地十个分支原共享树一致，正常索引为空。最终同步须使用本轮全部文件更新完成后的精确清单。
