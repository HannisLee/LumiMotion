# 透明度重置恢复窗口法线梯度配对与逐点裁剪审计

日期：2026-10-12，日本时间。服务器 ushas，Python `/home/han.li/miniconda3/envs/lumimotion-ushas/bin/python`。本修改只新增独立科学入口与日志子类，不修改已使用的 ambient、normal-opacity 核心、GaussianModel 或六个冻结评测文件。

## 科学决策

实际重读新旧 Goal、训练 03/04/05/06、脚部审计报告 1012-02，以及 T03/T04 的 `evaluation_14000/spatial_diagnostic/summary.json`。T03 full 的三项为 2.7576517427° / 5.3275671046° / 4.2877150228°；T04 detach 为 2.7561103847° / 5.4240755738° / 4.2873535823°。T04 鞋部更好，但人体与全局 Depth 略差，GS 的约 0.00154° 优势不足以支持稳定改善。两组鞋尖仍短，均 FAILED。

本轮选择 **T03 full@14000** 为共同源：保留其 Depth 和人体优势，以同一参数状态检验下一次真实 reset。T04 原结果完整保留，不把二者单项最低值拼接成成功。

假设：透明度被重置到不高于 0.01 后，expected-depth 自一致性会受到前后层混合影响；normal→opacity 可能与低透明度裁剪耦合，删除仍受 RGB 支持的表面。历史 T14 的零更新梯度和失效窗口支持该机制，但不是本轮成功保证。历史审计高度带 7303 像素与本目标 Sneakers 对象 6185 像素口径不同，不混用。

控制和候选从 14001 至 15000 均使用 **full**。15000 步先完成参数更新及原生增密/裁剪，再自然 reset。控制从 15001 起仍 full；候选仅从 15001 起 `detach_opacity`，持续至 16000。该差异只删除独立 normal 副本到 opacity 的导数；photo、Alpha、distortion 到 opacity 以及 normal 到 XYZ、rotation、scale 的路径仍在。前 1000 步的共同配方减少 reset 前状态分化，但 CUDA 执行可能存在微小非确定性，不声称独立进程逐位相同。

这是重置恢复窗口的单因素验证，预算是每组 2000 次更新，共 4000；另各 110 步独立冒烟，共 220。T03 鞋区占 GS 误差和 12.7120%，约贡献 0.3506°；在其他像素不变的条件下，即使鞋误差归零，全局仍约 2.4071°。Cloth 占误差和 41.4629%，人体总计 78.0146%。因此本轮同时检验机制和几何恢复，不预先承诺可单靠鞋修复达到 2°，也不按 GT 对象分区调整训练损失。

## 新实现与来源

- `scripts/train_static_dl_reset_audit.py`：独立入口，固定 T03@14000 的真实目录、PLY/deform/lighting SHA、两份来源 marker SHA及十项原科学源 SHA；加载仅原 135 训练相机，禁止加载测试图。全局 XYZ LR 仍沿原 30k 日程；两组重新建立零 Adam 动量与零增密累计，不能称为优化器无缝恢复。ambient 固定 0，原灯强、材质、几何、loss 权重和原拓扑设置继承。
- `scene/static_dl_reset_audit.py`：`AuditedGaussianModel` 继承冻结原类。clone、split、densification_postfix、prune、reset 的训练操作均调用原方法。新增选择计算只取父 UID 和核对原因，原方法仍接收原参数。无额外随机采样，无额外损失，无 GT 高度/对象/材质输入。
- normal 路由仍调用冻结 `scene/static_dl_normal_opacity.py`；photo 仍是冻结 `scene.static_dl_ambient.render_photometric(..., ambient_fraction=0)`。输出前向没有新公式。

正式 CLI：

```bash
python -m scripts.train_static_dl_reset_audit \
  --init_model output/1012-06-LH-static-jumpingjacks_DL_V2-G2-T03-normal透明度梯度控制2k/model_mlp \
  --init_iteration 14000 --model_path <独立正式输出>/model_mlp \
  --source_path output/1011-09-静态DL-Goal训练总控/data_view \
  --post_reset_normal_route full \
  --steps 2000 --save_steps 900 1000 1100 1200 2000 --seed 1012
```

候选仅把 `--post_reset_normal_route` 改成 `detach_opacity`，并使用另一个输出。实际 GPU 命令由 trainer 经项目 bootstrap/native snapshot launcher 执行并留完整命令，不能以这条示意命令冒充已运行。

冒烟加 `--smoke --steps 110 --save_steps 10 11 100 110`，独立 `output/smoke_test` 目录。它明确在 **14010 人工 reset**，从 14011 激活候选路线，14100 执行真实原生增密/裁剪。此人工时间只存在于 smoke；正式 reset 固定 15000，不提供可自由修改 reset 的 CLI。smoke 只覆盖实现分支，不能当作自然 15000 失效/恢复的科学证据。

## 检查点与阶段契约

正式保存 14900、15000、15100、15200、16000。15000 常规检查点是 **post-reset**；本步最后参数更新使用 full，下一更新才使用配置的 post-reset 路线。终点 16000 不再执行没有恢复机会的 topology/reset，延续此前共同 continuation 协议。

另外保存独立事件模型 `model_mlp/reset_event/pre_reset/model_mlp` 与 `.../post_reset/model_mlp`，包含 PLY、deform、lighting、cfg_args 和来源 marker。pre-reset 在本步增密/裁剪之后、reset 之前；post-reset 在 reset 之后。二者不覆盖常规模型，不能跨模型或跨阶段拼主指标。

`lighting.json` 中：

- `normal_opacity_route`：该检查点最后一次参数更新实际使用的路线。15000（smoke 14010）无论哪组均为 full。
- `next_update_normal_opacity_route`：之后下一步将用的路线。
- `post_reset_normal_route`：实验配置路线。
- `first_reset_iteration`：reset 前为 null；正式发生后为 15000，smoke 为 14010。
- `checkpoint_phase`：事件分别为 `pre_reset` / `post_reset`；常规 reset 步为 `post_reset`，其他常规检查点为 `after_update`。

训练 marker 为 `reset_audit_training.json`，日志 `reset_audit_metrics.jsonl`，完成标记 `reset_audit_finished.json`。不生成旧 `normal_opacity_training.json` 或 `ambient_training.json` 冒名副本。顶层/static/config 的 `pre_reset_normal_route=full`；`post_reset_normal_route` 同 CLI；CLI args 只有 post-reset 路线。移除继承的旧顶层/config `normal_opacity_route`，避免将其误读为全程路线。逐次日志另有 `effective_normal_opacity_route` 与 `first_reset_iteration`。

`new_sources` 精确为十二项：新 script、新 scene、旧 normal-opacity script/scene、ambient scene、photometric scene、censored scene、shadow_split scene、GaussianModel、gaussian_renderer/__init__、dataset_readers、camera_utils。来源用当前快照实际绝对路径和 SHA，旧十项内容必须与 T03 实际训练一致。

## 可审计逐点删除

`model_mlp/topology_audit/events.jsonl` 引用对应 NPZ。初始点 UID 与起点 PLY 行序一致；新点领取单调递增 UID，出生事件保存 parent_uid，split 新点父排列按原 `repeat(N)`，原有 UID 不回收。记录覆盖全部模型点，不用 GT 分区决定记录或更新。

- `clone_birth` / `split_birth`：新 UID、父 UID、出生 XYZ/opacity。
- `split_parent_replacement`：因拆分而移除父点，单独记录，**不当作低透明度裁剪损失**。
- `filter_prune`：原实际 mask 对应 UID、XYZ、opacity、scale，逐点 low_opacity / big_screen / big_world 布尔原因。原因可重叠，另报 union/overlap；每次强制核对原因并集与原删除 mask 精确一致。
- `initial` / `after_topology` / `pre_reset` / `post_reset` / `final`：全点 UID、XYZ、opacity、scale、rotation。可离线区分删除和迁移，重建谱系及 reset 前后变化。

记录的是原方法执行时的真实状态；原 densification_postfix 会重置 max_radii2D，屏幕尺度原因因此可能为零，不能用日志前的旧半径虚构裁剪原因。UID、CPU序列化和计数不修改优化器、已有梯度、增密累计或 RNG。日志不等于逐点因果证明：两独立组分化后，出生 UID 不能直接逐号匹配；须经各自父谱系和实际几何作离线分析。

## 验证及验收门槛

CPU 审计位于 `output/smoke_test/1012-08-staticDL-G2-reset拓扑CPU审计/`：从冻结原类提取实际拓扑/Adam方法，仅将设备 cuda 换成 cpu，并用共同 identity 旋转夹具；对照未插桩与插桩模型执行增密/裁剪→reset→再次裁剪。**7项 PASS**：每阶段参数/Adam/增密统计/RNG 精确一致；真实覆盖 clone 出生、split 出生及父替换、低透明度和世界尺度真裁剪、UID 唯一。该检查不运行 GPU，不替代实际原生冒烟。

入口保留原初始 photo 前向/六参数梯度审计，以及 normal 路由的十八项检查。首次 reset 后、下一次参数更新前，再运行同一真实 normal 路由检查，验证 full normal→opacity 非零、detach 为零、其余梯度/前向同义。额外核对已有参数梯度和密度统计哈希保持；该附加项使 post-reset 审计为十九项。原检查同时验证参数和 Torch RNG不变，任何失败均停下并保留现场。该调用使用本步原训练相机，不读测试或 GT 几何。

后续由 trainer 执行实际110步smoke，evaluator执行独立fresh；通过后再正式2k。正式终点16000使用原15完整协议与四类150方向，继续原GT对象离线诊断；reset附近的原保存检查点和删除日志只是辅助机制诊断，不替代主验收。目标仍是同一个模型 GS<2°、Depth≤5.8876060528°、Mesh≤4.7507435938°且整体几何完整。未达标保留全部失败资产并判 FAILED。此文记录实现和 CPU验证，未宣称已运行新GPU训练或已修好脚部。

## 首次快照冒烟失败与路径修正

首次 G2-T05/T06 冒烟分别在 `output/smoke_test/1012-06-staticDL-G2-T05-reset全梯度110步` 和 `output/smoke_test/1012-07-staticDL-G2-T06-reset阻断透明度110步`，均 exit=2，未进入模型训练、未执行参数更新。实际 `logs/train.log` 末尾为“共同源必须是已验收的G2-T03 full@14000”；完整 argv 在各自 `commands/train.json`。原因是 bootstrap 先将 cwd 切到源码快照，而旧入口以 `Path('output/...T03...').resolve()` 构造共同源，错误指向快照目录下的 output，拒绝了 launcher 正确传入的原仓库绝对模型路径。

修正仅改变路径门禁：从已通过固定 SHA256 的 `static_dl_training.json` 中读取 `args.model_path`，先要求其为绝对路径，再 resolve 后比较。原固定 T03 marker SHA、三个模型资产 SHA、十项旧科学文件 SHA 与实际共同源约束全部保留；未修改训练数学、路由、reset、拓扑或预算。初次快照和两个失败 smoke 完整保留，不回写旧快照或覆盖日志；重试应使用 root 新建的 retry1 快照和独立输出。

新增纯 CPU 路径检查在 `output/smoke_test/1012-08-staticDL-G2-reset拓扑CPU审计/path_retry1/`。检查从当前新入口 AST 提取实际路径门禁，在真实仓库 cwd 与原快照 cwd 下分别执行：两处均接受正确绝对来源、拒绝相对 marker 路径、拒绝错误来源，共 **6 项 PASS**。验证先核验真实来源 marker 固定 SHA，不导入 CUDA；该检查与 py_compile 均通过，不冒充真实 GPU 重试成功。
