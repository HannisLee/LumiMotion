# ELDL 定义与 RGB 色彩假设审查

日期：2026-10-30。服务器已核实为 `ushas`。仅静态只读检查当前数据 `_export/run_export.py`、`_export/skill_exporter_original.py` 与本轮实际调用代码；没有执行 Blender、打开场景快照或读取灯光 JSON、GT 法线、深度、反照率、材质、阴影和历史角度结果。

## EL 与 DL：能确认的定义及证据边界

数据目录为 `data/LH-data/static/LH-static-jumpingjacks-ELDL-V3`。`run_export.py:98-99` 注释说明记录贡献光照的点光和世界环境；第 118—127 行读取世界 Background 节点，将其描述为 `constant_background`、`hdri=False`。该环境字典只生成一次，第 130 行开始逐帧循环，并在第 160 行附到每一帧。第 203 行写入的场景说明也将世界环境称为恒定、SUN 称为绕行方向光。

因此当前导出源码的**设计语义**是静态角色、背景环境与点光贡献，加上随时间绕行的 SUN；这里不能把 ELDL 简化成“只有恒定标量环境和一个方向光”。固定表面的点光/环境贡献若在世界中静止且以漫反射为主，可以近似吸收到跨帧共享的每表面偏置中。

但这些代码不构成当前已保存场景所有 EL 分量实际跨帧恒定的严格证明：

- 世界环境值在循环外读取，随后重复使用，没有逐帧重新评估世界节点，也没有检查世界节点动画、驱动或连接图。
- 点光条目在第 130—155 行按各帧依赖图重新导出，却没有源码断言点光位置、颜色和强度跨帧恒定。本审查未打开输出值进行验证。
- 当前入口使用已有 Blender 场景；这里没有能够独立重建并验证全部 EL 动画状态的完整场景初始化源码。固定背景文字、一次性读取或缺少动画设置调用，本身不足以证明已加载场景没有动画。

因此只能确认“导出定义宣称恒定世界背景”，无法仅凭本次允许读取的源码确认所有 EL 贡献严格静止。实际方法中的每表面跨帧共享 `b` 应记录为近似假设；观察方向变化下的非漫反射贡献也可能偏离该假设。未据此扩张方法、引入逐帧环境或进行参数搜索。

## SUN 的方向和世界坐标

`skill_exporter_original.py:490-491` 的 `surface_to_sun_dir` 返回灯世界旋转作用于局部正 Z 轴后的单位向量。该文件第 494—509 行逐帧调用并写入顶层 `light_dir_world`。

`run_export.py:151` 对依赖图中的 SUN 再调用同一函数，第 157 行明确写入定义：从表面指向太阳的单位向量，漫反射项使用 `max(dot(normal, light_dir_world), 0)`。

故预测与最终 GT 应直接在相同世界坐标系比较 surface→light 方向，只归一化，不尝试取负或搜索坐标变换。没有读取任何真实帧灯向，也没有采用源码中的轨迹数值生成预测。

## RGB 颜色变换：目前无法静态证明为 Standard

原始导出器 `main` 在第 639—640 行先渲染 lit image。调用的 `render_png_sequence`（第 112—122 行）仅设置 PNG、RGBA、16 位和压缩，然后执行动画渲染；没有设置或记录 `scene.view_settings.view_transform`、look、曝光或 gamma。

`run_export.py` 对已有场景调用原导出器；当前源码未对 lit image 设置颜色管理。其修复分支第 65—79 行还会重用已经完整存在的 RGB。因此仅凭当前入口与原导出器，**无法确认原始 image 使用 Standard、AgX 或其他视图变换，也无法确认曝光为 0、gamma 为 1**。输出为 16 位 PNG 不能自动证明其可通过纯逆 sRGB 恢复线性辐射亮度。

需要特别区分的是 `render_albedo_png`：第 300—303 行保存颜色设置，第 317—320 行临时设为 Standard、None look、曝光 0、gamma 1，第 358—361 行恢复旧设置。该函数在 lit image 已经导出后执行。这些设置只适用于专门的反照率渲染，不能作为原始 RGB 的色彩证据；而且临时设置还位于允许失败继续的异常处理块中。

## 本轮方法与记录要求

实际提取代码 `LIHAN/scripts/static_rgb_light_extract.py` 对 RGB 应用标准分段逆 sRGB，再计算线性亮度；拟合代码 `static_rgb_light_fit.py` 使用固定方向光强度 1、每 Gaussian 跨帧共享的非负 `rho` 与 `b`。这两点应分别表述为“逆 sRGB 观测近似”和“静态每表面环境/点光贡献近似”，不是已经从当前场景证明的物理真值。

当前审查不调整 gamma、色彩变换、光强或共享环境模型，不读取 GT 补证，不增加候选集。最终若失败，应将色彩管理未确认、共享偏置近似和其他几何/可辨识性问题并列为可能局限，不能据此断言某项就是已验证的失败原因。
