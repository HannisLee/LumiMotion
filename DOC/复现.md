## 1. 数据集说明

`d-nerf-relight-spec32` 是论文使用的**合成动态重光照数据集**，基于 D-NeRF 的 5 个动态场景，在不同环境光照下渲染而成。

### 1.1 包含的场景

| 场景目录 | 说明 |
|---|---|
| `hook150_v5_spec32` | 动态场景 |
| `mouse150_v5_spec32` | 动态场景 |
| `jumpingjacks150_v5_spec32` | 动态场景 |
| `spheres_v5_spec32` | 动态场景 |
| `standup150_v5_spec32` | 动态场景 |
| `*_statictimestep1` / `*_statictimestep75` | 对应场景的**静态单帧**版本（用于 static 评估） |

每个场景 150 帧：`transforms_train.json` 含 **135 个训练相机**，`transforms_test.json` 含 **15 个测试相机**。

### 1.2 单场景目录结构（以 `hook150_v5_spec32` 为例）

```
hook150_v5_spec32/
├── config.json                              # 记录默认 train/test 光照（代码不读，仅参考）
├── points3d.ply                             # 初始点云（3DGS 初始化用）
├── transforms_train.json                    # 训练相机位姿 + 时间步
├── transforms_test.json                     # 测试相机位姿 + 时间步
│
├── chapel_day_4k_32x16_rot0/                # ┐
│   └── r_0001.png ... r_0150.png (150张)    # │ 4 个环境光照下的渲染 RGB 图像
├── chapel_day_4k_32x16_rot0.hdr             # │ 每个对应一个 .hdr 环境贴图
├── dam_wall_4k_32x16_rot90/  + .hdr         # │
├── golden_bay_4k_32x16_rot330/ + .hdr      # │
├── small_harbour_sunset_4k_32x16_rot270/+.hdr# ┘
│
├── albedo/        # GT albedo 图 (r_00010001.png ...)  —— 材质评估 + albedo 缩放用
├── depth/         # GT 深度图
└── dynamic_mask/  # 动态物体掩码 (mask_0001.png ...)
```

`transforms_*.json` 每帧字段：`file_path`（图像名，如 `r_0001`）、`rotation`、`transform_matrix`（4×4 相机到世界）、`time`（归一化时间步，0~1）。

### 1.3 LumiMotion 实际使用了哪些数据

| 数据 | 是否被代码使用 | 用途 |
|---|---|---|
| `transforms_train/test.json` | ✅ **使用** | 相机位姿 + 时间步 `time`（驱动形变 MLP） |
| `<envmap>/*.png`（光照文件夹） | ✅ **使用** | 训练 GT 图像（`original_image_train_light`）、NVS/relight 评估的 GT |
| `<envmap>.hdr` | ✅ **使用** | relight 评估时作为**未见过的测试光照** |
| `points3d.ply` | ✅ **使用** | 高斯点云初始化 |
| `albedo/*.png` | ✅ **使用** | 材质质量评估、albedo 全局缩放标定 |
| `roughness/*.png`（**仅 `_statictimestep` 版本有**） | ✅ **使用** | 仅 `eval_material_static` 评估 roughness 用（动态数据集没有此 GT） |
| `config.json` | ❌ 未读 | 代码读 CLI 的 `--train_light_folder/--test_light_folder`，不读此文件 |
| `depth/*.png` | ⚠️ 不直接监督 | 训练的深度/法线正则用的是**光栅化产生的渲染深度**，不是 GT；GT 深度不参与主流程 |
| `dynamic_mask/*.png` | ❌ 未引用 | 动/静分割由**二值分离特征无监督学习**完成（论文核心），不需要 GT mask |

> **要点**：LumiMotion 不需要 `dynamic_mask` 或 `depth` 这类 GT——动态分割是模型自己学的。它真正依赖的是：**相机位姿+时间**、**某光照下的 RGB**、**`.hdr` 环境贴图**、**albedo GT**（评估用）。

### 1.4 4 个光照环境与组合

数据集提供 4 个环境贴图（`spec32` = 32 分辨率环境贴图）：

| 环境光照名 | 旋转 |
|---|---|
| `chapel_day_4k_32x16_rot0` | 0° |
| `dam_wall_4k_32x16_rot90` | 90° |
| `golden_bay_4k_32x16_rot330` | 330° |
| `small_harbour_sunset_4k_32x16_rot270` | 270° |

`bash_scripts/synthetic_results_from_paper.sh` 定义了 3 种 **train|test 光照组合**（训练用一种光照，重光照评估用另一种未见光照）：

| 组合名 | 训练光照（train） | 测试光照（test，重光照） |
|---|---|---|
| `chapelday_goldenbay` | `chapel_day_4k_32x16_rot0` | `golden_bay_4k_32x16_rot330` |
| `damwall_harbour` | `dam_wall_4k_32x16_rot90` | `small_harbour_sunset_4k_32x16_rot270` |
| `goldenbay_damwall` | `golden_bay_4k_32x16_rot330` | `dam_wall_4k_32x16_rot90` |

> `chapel_day_4k_32x16_rot0`（训练）和 `golden_bay_4k_32x16_rot330`（测试）正好是代码默认值，下文示例沿用这一组合。

## 2. 通用约定（必读陷阱）

1. **`--model_path` 会被自动加上 `_mlp` 后缀**：传 `--model_path outputs/hook`，实际写到 `outputs/hook_mlp/`。**下游所有命令传相同的原始路径**（`outputs/hook`），不要手动加后缀。
2. **`--depth_ratio`**：Stage 1 必须 `1.0`；Stage 2 及所有 render/eval 用 `0.0`（论文合成设定）。
3. **`--source_path` / `--model_path` 必传**；合成场景标准组合：`--is_blender --eval --gt_alpha_mask_as_scene_mask --resolution 2`。
4. 两阶段写**同一个** `--model_path`，Stage 2 通过 `--load_iter 35000` 读取 Stage 1 产物。

## 3. 两阶段训练命令（分开运行）

> ✅ **是的，两阶段是分开的两条独立命令，需要分别运行。** 先跑 Stage 1（约 35000 步），完成后再跑 Stage 2（从 35000 续训到 55000）。

### 3.1 Stage 1 —— 几何训练（→35000 步）

```bash
conda activate lumimotion-cu129

python -m scripts.train_stage1 \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --gt_alpha_mask_as_scene_mask --resolution 2 \
  --iterations 35000 \
  --train_light_folder chapel_day_4k_32x16_rot0 \
  --densify_until_iter 20000 \
  --lambda_separation 0.001 --d_xyz_loss_weight 0.001 \
  --binarization_warm_up 1000 \
  --depth_ratio 1.0 \
  --d_color_reg_loss_weight 0.01
```

- 训练高斯几何 + 形变 MLP + **二值分离特征**（动/静分割）。
- 产物写入 `outputs/hook_mlp/`：`point_cloud/iteration_35000/point_cloud.ply`、`deform/iteration_35000/deform.pth`。
- `lambda_separation` / `d_xyz_loss_weight` 因场景而异，见[第 8 节配置表](#8-各场景超参配置表)。

> **【当前分支新增】光度 Lambertian 模式**（可选）：加 `--render_mode photometric_lambertian` 可启用一种替代的颜色渲染路径（每时间步一对可学习光照），默认关闭即 `original`。论文复现不需要开启。

### 3.2 Stage 2 —— 材质/重光照训练（35000 → 55000 步）

```bash
python -m scripts.train_stage2 \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --gt_alpha_mask_as_scene_mask --resolution 2 \
  --iterations 55000 --load_iter 35000 \
  --diffuse_sample_num 512 \
  --train_light_folder chapel_day_4k_32x16_rot0 \
  --depth_ratio 0.0
```

- **冻结几何**，只训练 albedo / roughness / opacity + 形变 MLP 的颜色头 + 可学习 `EnvLight`。
- `--load_iter 35000` 加载 Stage 1 的检查点。
- 产物：`point_cloud/iteration_55000/`、`deform/iteration_55000/deform.pth`、`envmap/iteration_55000/{envmap.pth, envmap.hdr}`。

## 4. 评估命令

> 必须先完成 Stage 2。评估分 **static**（静态单帧）和 **dynamic**（完整运动）两套，每套都按 `scale_albedo → eval_material → eval_relight → eval_nvs` 顺序执行。
> **`scale_albedo_*` 必须在对应 eval 之前运行**（它产出 albedo 全局缩放因子 JSON，eval 会读取）。

### 4.1 Static 评估链（固定静止帧）

```bash
# ① 估计 albedo 全局缩放（会自动查找 *_statictimestep1 数据集）
python -m scripts.scale_albedo_static \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --eval --is_blender --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 \
  --test_light_folder golden_bay_4k_32x16_rot330 \
  --resolution 2 --depth_ratio 0.0
  # 若自动查找失败，手动指定：--static_source_path data/d-nerf-relight-spec32/hook150_v5_spec32_statictimestep1

# ② 材质评估（albedo + roughness）
python -m scripts.eval_material_static \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --eval --is_blender --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 \
  --test_light_folder golden_bay_4k_32x16_rot330 \
  --resolution 2 --depth_ratio 0.0

# ③ 重光照评估（未见过的测试光照下）
python -m scripts.eval_relight_static \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --eval --is_blender --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 \
  --test_light_folder golden_bay_4k_32x16_rot330 \
  --resolution 2 --diffuse_sample_num 2048 --depth_ratio 0.0

# ④ NVS 评估（训练光照下的新视角合成；用学到的 EnvLight，需 train_light_folder）
python -m scripts.eval_nvs_static \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --eval --is_blender --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 \
  --resolution 2 --diffuse_sample_num 2048 --depth_ratio 0.0
```

### 4.2 Dynamic 评估链（完整运动）

把上面 4 条命令的脚本名 `_static` 换成 `_dynamic`，并去掉 `--static_source_path`（动态评估用主数据集自身的 albedo GT，无 roughness 评估）：

```bash
python -m scripts.scale_albedo_dynamic  ...  # 参数同上（4.1①）
python -m scripts.eval_material_dynamic ...  # ② 无 roughness
python -m scripts.eval_relight_dynamic  ...  # ③
python -m scripts.eval_nvs_dynamic      ...  # ④
```

### 4.3 评估产物

| 脚本 | 结果 JSON | 指标 |
|---|---|---|
| `eval_material_static` | `results_material_static.json` | albedo PSNR/SSIM/LPIPS + roughness MSE |
| `eval_material_dynamic` | `results_material_dynamic.json` | albedo PSNR/SSIM/LPIPS |
| `eval_relight_static/dynamic` | `results_relight_static/dynamic.json` | PBR PSNR/SSIM/LPIPS |
| `eval_nvs_static/dynamic` | `results_nvs_static/dynamic.json` | NVS PSNR/SSIM/LPIPS |

### 4.4 【新】更彻底的逐帧诊断评估（可选）

不在流水线里，可单独运行，输出每帧对比图 + 更全指标：

```bash
# Stage 1 在动态帧上的几何/外观重建（用普通 render，非 IR）
python -m scripts.eval_stage1_dynamic \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --resolution 2 --load_iter 35000 \
  --train_light_folder chapel_day_4k_32x16_rot0 --depth_ratio 1.0

# Stage 2 在动态帧上的 PBR 重建（内置 albedo 缩放，无需 static 数据集）
python -m scripts.eval_stage2_dynamic \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --resolution 2 --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 --depth_ratio 0.0
```

## 5. 可视化命令（输出图片/视频）

> 想看训练效果、生成图片/视频，用这些脚本。它们不计算指标，只产出可视化。

### 5.1 Stage 1 诊断可视化（`render_stage1_insights`）

在 Stage 1 训练后运行，输出完整渲染 / alpha / 法线 / albedo / 小高斯 / **二值分离着色**等多种诊断图 + mp4：

```bash
python -m scripts.render_stage1_insights \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --resolution 2 --load_iter 35000 \
  --train_light_folder chapel_day_4k_32x16_rot0 --depth_ratio 0.0
# → outputs/hook_mlp/renders_stage1_insights/ours_35000/
```

### 5.2 Stage 2 材质可视化（`render_materials`）

在 Stage 2 训练后运行，可视化全部时间步的 albedo（sRGB）与 roughness，并生成 mp4：

```bash
python -m scripts.render_materials \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --resolution 2 --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 --depth_ratio 0.0
# → outputs/hook_mlp/trained_materials/ours_55000/  (Albedo_cam{N}.mp4, albedo_cam{N}_{ts}.png ...)
```

### 5.3 用任意 HDR 重新打光（`render_relight_with_hdr`）

加载任意外部 `.hdr` 对场景重新打光，生成视频（无 GT，纯展示）：

```bash
python -m scripts.render_relight_with_hdr \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --resolution 2 --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 --depth_ratio 0.0 \
  --hdr example_envmaps/your_envmap.hdr
# → outputs/hook_mlp/render_relight_with_hdr_<hdr名>/ours_55000/
#   可加 --colmap_convention（若 HDR 方向约定不同）
```

### 5.4 旋转光源视频（`render_relight_with_rotating_envmap`）

手动构造"单像素点亮"的 HDR 模拟旋转光源，逐像素扫描生成视频（默认被注释在流水线里）：

```bash
python -m scripts.render_relight_with_rotating_envmap \
  --source_path data/d-nerf-relight-spec32/hook150_v5_spec32 \
  --model_path outputs/hook \
  --is_blender --eval --resolution 2 --load_iter 55000 \
  --train_light_folder chapel_day_4k_32x16_rot0 --depth_ratio 0.0 \
  --diffuse_sample_num 2048
# → outputs/hook_mlp/render_relight_with_rotating_light/ours_55000/
```

### 5.5 评估脚本本身也输出图片

所有 `eval_*` 脚本除了写 JSON，还会在 `outputs/hook_mlp/eval_*/ours_<iter>/` 下输出 render/mask/gt/error 等对比 PNG。所以想"边评估边出图"，直接跑[第 4 节](#4-评估命令)的 eval 命令即可。

## 6. 一键复现脚本

完整端到端流水线（Stage1 → render_stage1_insights → Stage2 → render_materials → static/dynamic 全套 eval）在：

```bash
bash bash_scripts/synthetic_results_from_paper.sh
```

它会遍历 **3 种光照组合 × 5 个场景**，自动按场景查表设置 `lambda_separation`/`d_xyz_loss_weight`。可按需注释/修改其中的 `CONFIGS`、`LIGHTS`、`OUTPUT_BASE` 来只跑单个场景。该脚本是标志组合的**权威来源**。

> ENeRF / DNA 数据集各有独立脚本：`bash_scripts/enerf-actor1.sh`、`enerf-actor3.sh`、`dna_*.sh`（需自备不可再分发数据）。

## 7. 全部可选项速查

### 7.1 通用参数（所有脚本共享，来自 `arguments/__init__.py`）

**ModelParams（加载参数）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--source_path` | `""` | 数据根目录（必传） |
| `--model_path` | `""` | 输出目录（必传，**自动加 `_mlp` 后缀**） |
| `--sh_degree` | `3` | 球谐阶数 |
| `--train_light_folder` | `chapel_day_4k_32x16_rot0` | 训练光照子目录 |
| `--test_light_folder` | `golden_bay_4k_32x16_rot330` | 重光照评估光照子目录 |
| `--resolution` | `-1` | `-1` 自动按宽 1600 下采样；`1/2/4/8` 显式倍率（合成用 `2`） |
| `--white_background` | `False` | 白色背景 |
| `--eval` | `False` | 划分训练/测试集 |
| `--load2gpu_on_the_fly` | `False` | OOM 时启用，图像留 CPU 逐相机传输 |
| `--is_blender` | `False` | Blender 数据集标志 |
| `--deform_type` | `mlp` | 形变网络类型（决定 model_path 后缀） |
| `--hyper_dim` | `1` | 动静分离变量维度 |
| `--pred_color` | `True` | 是否预测颜色形变 |
| `--no_binary_separation` | `False` | 关闭二值分离 |

**PipelineParams（管线参数）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--render_mode` | `original` | `original` 或 `photometric_lambertian`（新） |
| `--depth_ratio` | `1.0` | 深度混合；**Stage1 用 1.0，Stage2/eval 用 0.0** |
| `--diffuse_sample_num` | `256` | 漫反射入射光采样数（训练用 512，relight/nvs 评估用 2048） |
| `--light_t_min` | `0.1` | 阴影光线起始偏移 |
| `--wo_indirect` / `--wo_specular` / `--detach_indirect` / `--wo_indirect_relight` | `False` | IRGS 消融开关（默认全 False = 完整模型） |

**OptimizationParams（优化参数，节选关键的）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--iterations` | `80000` | 总迭代数（Stage1 用 35000，Stage2 用 55000） |
| `--warm_up` | `1000` | 形变 MLP 预热步 |
| `--binarization_warm_up` | `1000` | 二值分离启动步 |
| `--densify_until_iter` | `15000` | 致密化终止步（合成 Stage1 用 20000） |
| `--lambda_separation` | `0.005` | **二值分离损失权重**（因场景而异） |
| `--d_xyz_loss_weight` | `0.001` | 位移正则权重（因场景而异） |
| `--d_color_reg_loss_weight` | `0.01` | 颜色形变正则权重 |
| `--lambda_dist` | `1000` | 畸变正则权重 |
| `--lambda_dssim` | `0.2` | D-SSIM 损失权重 |
| `--lambda_alpha_loss` | `0.1` | alpha mask BCE 权重 |
| `--envmap_resolution` | `32` | EnvLight 分辨率 |
| `--envmap_activation` | `exp` | EnvLight 激活函数 |
| `--envmap_init_value` | `1.5` | EnvLight 初始值 |
| `--trace_num_rays` | `262144` | 光线追踪采样数 |
