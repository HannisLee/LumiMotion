# CV3s：SH 优于 GT 光 Lambertian 的原因审计报告

日期：2026-08-24  
服务器 / 环境：`garuda` / `lumimotion-garuda`

## 1. 审计问题与结论

本报告审计的问题是：CV3s 上，为什么默认 SH 颜色管线不仅 RGB 更好，法线也明显优于使用 GT 灯位的 Lambertian / per-light 管线？

结论是：**目前没有发现新的坐标、法线变换或梯度断链证据；主要矛盾已经不是“管线是否接通”，而是“所用 GT 信息并不等于 GT 成像模型”，再叠加 SH 基线拥有远强于 Lambertian 的外观拟合自由度，以及当前数据没有把相机、时间和光照解耦。**

因此，“per-light 理论上是改进点”与“同轨迹 RGB/normal 暂时输给 SH”并不矛盾：

- SH 的目标更接近对已观测图像做高容量拟合，天然容易取得更高重建指标；
- per-light 的价值应主要体现在可解释分解、未见光照组合与 relighting，而不是保证在同一条相机—光照轨迹上超过自由 SH；
- 当前 Lambertian 只使用了 AREA 灯中心位置所导出的方向，遗漏了面积、局部方向、距离、遮挡、软阴影和间接光等真实成像因素。错误的 RGB 残差会反过来推动 albedo、independent normal 和几何去代偿模型缺项。

按当前证据强度，原因优先级如下：

1. **高置信：GT 灯位被降维成了非 GT 的单方向 Lambertian。**
2. **高置信：SH 基线是更强的外观模型，而且还带时间条件颜色调制。**
3. **高置信：单灯 RGB 对 albedo 与 normal 本来就不可充分辨识，错误光照模型会进一步放大歧义。**
4. **高置信：当前相机、时间、灯光是一一绑定的单条轨迹，SH 很容易做轨迹插值。**
5. **中高置信：Lambertian 的 RGB 梯度会直接经过 normal，而 SH 的颜色可以绕开法线解释阴影，因此 SH 更容易保住几何法线。**
6. **次要但必须说明：原始法线数字评估对象不同，不过补做同口径评估后，真实几何差距仍然存在。**

## 3. 最关键原因：这里的“GT light”只是部分 GT

### 3.1 数据是真实 AREA 灯，训练却使用单一方向光

数据的 `lights.json` 明确记录：

- `source_type = AREA`；
- 方形面积灯，`area_size = 1.25`；
- Blender 原始强度 `1800`；
- 每帧记录灯中心的 `light_pos_world`。

见 `data/LH-data/static/only_clothV3/lights.json:2-18`。

但 `gt_directional` 的实际实现是：

1. 只读取 `light_pos_world`，见 `scene/photometric_lambertian.py:396-420`；
2. 用“灯中心 → 一个固定场景中心”计算每帧唯一方向，见 `scene/photometric_lambertian.py:422-438`；
3. 将该方向应用到本帧所有 Gaussian，并明确忽略距离，见 `scene/photometric_lambertian.py:440-463`；
4. 最终仅计算 `albedo / pi * I * max(n·l, 0)`，见 `scene/photometric_lambertian.py:580-640`。

所以当前所谓 GT light 更准确的名称应是：

> **GT AREA 灯中心位置派生的单一方向近似。**

它不是 Blender GT 光传输，也没有使用 AREA 灯的面积和朝向。

### 3.2 新增空间误差量化

本次使用 `0823-01` checkpoint 保存的真实 reference center、120 帧 GT 灯位以及点云范围，比较了：

- 训练实际使用的“灯中心 → 场景中心”方向；
- “灯中心 → 每个 Gaussian 位置”的局部方向。

对 SH iteration 35000 的 15,135 个 Gaussian、120 帧共约 181 万个位置—灯光组合，结果为：

| 项目 | P5 | 中位数 | P95 | 最大值 |
|---|---:|---:|---:|---:|
| 局部方向相对中心方向的夹角 | 2.570° | **6.546°** | **14.723°** | 17.122° |
| 若采用点光，局部逆平方项 / 中心逆平方项 | 0.786 | 1.003 | 1.261 | 1.760 |

点云跨度约为 `2.88 × 3.11 × 2.32`，而灯到 reference center 的距离为 `6.45–8.62`。这不是可以无条件忽略的远场光源：同一帧、不同位置的入射方向和辐照度存在系统性差异。

同时，即使先不考虑距离，AREA 灯仍然还缺少：

- 面积采样和软阴影；
- 场景遮挡 / visibility；
- 间接光与环境光；
- 非纯漫反射材质、镜面或粗糙度效应；
- Blender 色彩管理和剩余曝光差异。

### 3.3 历史 GT pass 标定已经证明模型上限不高

历史 directional 标定不是只用训练结果反推，而是直接使用 120 帧 GT RGB、GT albedo、GT normal 和灯位。即使所有几何量都给 GT，最佳全局强度 `5.5043499` 下，前景 PSNR 也只有均值 `16.318 dB`；每帧最佳强度还从 `4.6097` 变化到 `6.5789`。证据见：

- `output/0816-only_clothV3-coordinate-pipeline-audit/calibration_camera_facing/calibration.json`
- `DOC/报告/08.18.only_clothV3-Directional光强标定报告.md`

这条证据很关键：**当 GT albedo 与 GT normal 都无法让当前单方向公式复现 Blender 图像时，训练中的 normal 就必然会收到“去补偿模型残差”的压力。** 换句话说，灯位置是 GT，不代表损失的最优 normal 就是 GT normal。

## 4. SH 基线不是和 Lambertian 同容量的公平外观对照

### 4.1 degree-3 SH 每个 Gaussian 有 48 个颜色系数

degree-3 SH 有 16 个基函数，每个 RGB 通道各一组，即每个 Gaussian 最多 48 个外观标量。渲染时根据相机到 Gaussian 的方向计算 view-dependent color，见 `gaussian_renderer/__init__.py:249-269`。

Lambertian 分支则只有：

- 3 个 albedo 值；
- 一个归一化 normal，约 2 个有效自由度；
- 固定的单方向和全局强度；
- 无可见性、间接光或材质残差分支。

它不是“给了更多 GT 所以容量也更强”，而是“给了一个更强物理约束，但这个约束与真实成像不完全一致”。约束一旦有偏，容量越小越难把 RGB 拟合好。

### 4.2 SH 还实际使用了时间条件 `d_color`

三个实验的 `cfg_args` 都包含 `pred_color=True`。形变网络对位置和时间编码后，另有一个颜色 MLP，见 `utils/time_utils.py:80-98`、`140-170`、`172-206`。

在 SH 分支，`d_color` 的前三维会直接调制 DC 颜色，见 `gaussian_renderer/__init__.py:249-258`。训练只对它施加有限的 L2 正则，见 `scripts/loss.py:510-527`。

在 photometric Lambertian 分支，颜色在前面的物理分支直接预计算，随后不会进入 SH 的 `d_color` 调制分支，见 `gaussian_renderer/__init__.py:129-157`、`238-269`；`d_color` 正则也只在 `not photometric_active` 时启用。

所以当前 SH 基线的准确描述是：

> **degree-3 view-dependent SH + 时间条件的 per-Gaussian DC 颜色调制。**

它可以把阴影、间接光、材质残差和一部分时序变化直接吸收到外观里，不必让几何法线承担这些误差。这既解释了极高 PSNR，也解释了为什么它可能保留更好的 GS normal。

## 5. CV3s 数据没有解耦相机、时间和光照

CV3s 共有 120 帧、120 个唯一相机矩阵，训练 105 帧，测试 15 帧；测试集就是每隔 8 帧抽一帧，见 `data/LH-data/transfer-static/only_clothV3/dataset_manifest.json:5-18`、`128-145`。

每帧同时只有一个相机状态和一个灯光状态。它们由同一个 frame/time 索引决定，因此训练数据没有覆盖“同一相机看多个灯”或“同一灯下多个独立相机”的笛卡尔组合。

本次额外检查发现：

- 第 1 帧相机位置与 AREA 灯中心位置完全相同，数据证据见 `lights.json:5-8` 和 `camera.json:107-110`；
- 全 120 帧相机—灯中心距离均值为 `3.532`，范围 `0–6.447`；
- 相机→中心方向与灯→中心方向夹角均值 `26.13°`，P95 `48.22°`。

这里不能简单说“相机和灯全程共点”，因为后半程差异不小；但可以确认它们是由同一个时间索引驱动的两条平滑、确定性轨迹。SH 的 view direction 加上 `d_color(time)` 足以学习这条轨迹的外观映射，而 stride-8 测试只是同轨迹插值。

因此，当前 `52.56 dB` 有力证明 SH 很会重建这条轨迹，但**不能证明 SH 学到了可迁移的光照分解，也不能据此否定 per-light 的 relighting 价值**。

## 6. 为什么 Lambertian 会把法线和几何带偏

### 6.1 单灯 RGB 对 albedo 与 normal 不充分可辨识

当前每个样本近似满足：

```text
RGB = albedo × I × max(normal · light, 0)
```

在一个已知灯方向下，RGB 主要只约束 `albedo × (normal·light)` 的乘积。未知 albedo 和二维 normal 方向之间存在大量等价或近等价解；单个标量 `n·l` 也不能唯一确定三维 normal。

多视角 `live` / `mv` normal loss 能提高自一致性，但不是 GT 正确性监督：

- GS normal loss 比较 raster normal 与当前深度导出的 surface normal，见 `scripts/loss.py:298-314`；
- independent normal 的 live / mv 项是免 GT 一致性，见 `scripts/loss.py:421-455`；
- GT-normal oracle 默认关闭，只是诊断项，见 `scripts/loss.py:379-419`。

因此，一个系统性偏离 GT、但跨视角一致的 normal 仍可能是训练最优解。

### 6.2 错误 RGB 残差在 Lambertian 中直接经过 normal

Lambertian 的 RGB 必须通过 `max(n·l,0)` 产生。只要面积灯、遮挡或间接光没有建模，optimizer 就会尝试通过以下变量代偿：

- independent normal；
- albedo；
- Gaussian rotation / position / opacity 和 alpha 混合。

这也解释了补评结果：不仅 independent normal 是 `19.23°`，同一模型的 GS raster normal 也退化到 `20.53°`。也就是说，误差已经从 shading normal 传到了几何 / 深度表示。

相比之下，SH 可以直接改变外观系数与 `d_color`，不要求每一个阴影变化都由几何法线产生；默认 GS normal 更容易被 2DGS 的深度—法线一致性保持住。

### 6.3 暗部存在硬截断梯度问题

代码使用 `ndotl.clamp_min(0.0)`，见 `scene/photometric_lambertian.py:616-619`。当 `n·l <= 0` 时，RGB 对 normal 的局部梯度为零。恰好在背光、遮挡和低亮区域，独立法线最需要额外约束，却最缺少光度梯度。

### 6.4 alpha compositing 进一步扩大等价解

图像像素是多个 Gaussian 的颜色、albedo、normal 与 opacity 混合结果，而离线 normal 图又是另一次 alpha-normalized normal 混合。不同的 Gaussian 组合可以产生相似 RGB，但对应完全不同的平均法线。轮廓、高频褶皱和半透明边缘因此尤其容易出现高角误差。

## 7. 既往审计如何约束本次结论

本次没有重复推翻已经通过的管线审计，而是把已有结论作为前提：

1. `DOC/报告/08.16-only_clothV3坐标与Lambertian管线复审.md` 和 `DOC/报告/08.16.Lambertian渲染代码与坐标系全流程审计.md` 已检查世界坐标、灯方向、normal 约定与线性 / sRGB 顺序；目前没有新反例。
2. `DOC/报告/08.18-N0-GTnormal-oracle实验与下一轮建议.md` 证明：冻结其他变量、关闭 RGB、只用 GT normal 监督 independent normal，100 步内 CV3 从 `25.598°` 降到 `21.136°`，CV3L 从 `24.809°` 降到 `20.174°`。因此 independent normal 参数、变形相对法线、raster map、GT EXR 坐标和 evaluator 是可导且可恢复的。
3. `DOC/报告/08.16-前500步梯度与法线崩坏审计报告.md` 观察到 RGB / DSSIM / alpha 在早期推动 rotation / geometry，并与法线恶化同时发生；但历史报告也正确指出，真正的方向性因果还需要 RGB 梯度与 GT-normal diagnostic 梯度的 cosine audit。
4. `DOC/报告/08.16-固定几何仅Albedo训练对照报告.md` 已表明固定几何可以避免法线继续恶化，但不能证明 RGB 梯度方向正确。

综合这些证据，更合理的判断是：

> **normal 链路本身可以恢复；RGB-only 目标在当前不完整光照模型和单轨迹数据下，选择了另一个能解释图像但不等于 GT normal 的解。**

## 8. 下一步最有判别力的实验

### P0：先测模型和数据，而不是继续扫 normal loss 权重

1. **同 checkpoint 双法线评估**  
   `0823-01` 已补完。建议对 `0824-01` 也同时输出 independent normal 与 GS raster normal，后续所有报告固定双口径，避免把 shading normal 与 geometry normal 混为一谈。

2. **SH 容量消融**  
   在同一个 SH checkpoint 上依次渲染：完整 degree-3 + `d_color`、关闭 `d_color`、SH degree 0、仅 DC。若 PSNR 大幅下降，就能定量确认 SH 优势中有多少来自轨迹记忆与 view-dependent 外观，而不是几何。

3. **GT pass 成像上限对照**  
   固定 GT albedo、GT normal 与几何，比较：
   - 单一 `gt_directional`；
   - `gt_point_direction_only`，每个 Gaussian 使用局部方向；
   - `gt_point`，加入距离衰减并重新标定强度；
   - 4 / 16 点 AREA 采样；
   - AREA 采样 + visibility。

   这一步应先回答“模型本身最高能到多少 PSNR”，再跑 35k 训练。否则训练结果混合了模型误差与优化误差。

4. **N1 梯度方向审计**  
   在冻结几何的同一 batch 上，同时计算 RGB loss 与 GT-normal oracle loss 对 independent normal 的梯度，统计 cosine。它能直接回答：当前 RGB 残差究竟在改善 normal，还是系统性把 normal 推离 GT。

### P1：验证 per-light 真正主张

1. 构造相机 × 灯光的交叉数据：同一相机 / 几何下多个灯位，或同一灯位下多个相机。
2. 训练时留出未见过的 camera-light 组合，单独评估 relighting，而不是只做 stride-8 同轨迹插值。
3. 如果目标允许，可对高置信区域加入少量 GT-normal prior；若不允许 GT normal，则至少对低 `n·l`、阴影和 alpha 边缘使用置信度 mask，避免错误光度残差主导法线。
4. 在主 Lambertian 之后增加受控的 residual appearance head，用于吸收间接光和材质残差；但必须单独限制其容量并做 relighting 验收，否则它会重新退化成 SH 式记忆。

### 正在运行的相关实验

`output/0824-04-CV3s-GTposition_perGSdir_3ncons/` 正在用 `gt_point_direction_only` 测试逐 Gaussian 局部方向。这是正确且有价值的单变量消融，但它只修复本报告指出的一部分误差：仍未加入距离、AREA 采样、visibility、间接光和材质残差。完训前不应使用其中间指标下最终结论。

## 9. 最终判断

本次审计不支持“per-light 管线又存在一个明显坐标 bug”这一判断，更支持以下因果链：

```text
AREA / 遮挡 / 间接光的 Blender 图像
        ↓ 被压成
单一中心方向 Lambertian + 固定全局强度
        ↓ 产生结构化 RGB 残差
albedo / independent normal / geometry / alpha 被迫代偿
        ↓
RGB 与 normal 均弱于高容量 SH
```

与此同时，SH 使用 degree-3 view-dependent radiance 和时间条件颜色调制，在相机—灯光—时间绑定的单条轨迹上拥有明显的拟合优势。它取得更高 PSNR 与更好 GS normal 是合理现象，不代表 per-light 的理论价值不存在；它说明目前实验协议主要奖励“已观测轨迹重建”，还没有真正奖励“正确光照分解与未见光照泛化”。

后续判断 per-light 是否成立，最关键的两个门槛是：

1. 用 GT pass 证明所选光照模型的成像上限足够高；
2. 用解耦的 camera-light 组合证明 relighting 泛化，而不是只和 SH 比同轨迹 PSNR。
