## 技术摘要

当前 Stage 1 的 Lambertian 总损失不是“GT normal 监督”。它是以渲染 RGB 为主、以 rasterizer 的法线—深度自一致性与深度失真为几何正则、以 alpha BCE 为前景轮廓监督，并附加形变幅度、动态/静态二值特征与可学习光线平滑的复合目标。GT normal EXR 完全不进入 `loss.backward()`；它只在独立脚本中被拿来做训练后图像空间 normal 评估。

对 0811 的有效训练命令而言，训练从 iteration 1 到 10,000 仍是原始 SH 渲染；iteration 10,001 才切换为 Lambertian。由于该实验使用 `gt_point`，光方向并不学习，所以 Lambertian 的 light-smooth loss 恒为 0。其显式前景 alpha 监督开启，权重为 0.1；normal regularizer 从 8,001 iteration 开始以固定 0.02 启用；depth-distortion 的默认权重为 1000。后两项是数值尺度需重点观察的几何正则，而不是与 GT normal 的角度误差。

最重要的结论：如果目标是“最后 GS normal 与 GT normal 的差值变小”，现有目标只有间接约束，不能保证该指标下降。RGB 可被 albedo、opacity、position、rotation、形变和光照的退化组合解释；此外 camera-facing normal 的符号随观察相机变化。若要优化 GT normal 指标，必须明确加入经过像素对应、坐标对齐和可见性筛选后的 normal supervision，或至少增加 sign-invariant normal loss 的独立消融。

## 2. 先定义符号与有效像素范围

设渲染输出为 `I ∈ [0,1]^(3×H×W)`，GT 训练图为 `G ∈ [0,1]^(3×H×W)`，rasterizer 累积 alpha 为 `A ∈ [0,1]^(1×H×W)`。所有 `mean()` 都是对其张量的所有元素求均值，除非另行说明。

| 符号 | 代码变量 | 语义 | 备注 |
|---|---|---|---|
| `I` | `image` | 最终用于 RGB loss 的 sRGB 渲染图 | Lambertian v5 中先在线性空间 alpha 合成、后转 sRGB |
| `G` | `gt_image` | `original_image_train_light` | RGB 已被 loader clamp 到 `[0,1]` |
| `A` | `render_pkg_re['rend_alpha']` | 2DGS 像素覆盖/累积 alpha | 既用于 BCE，也用于 PBR 前景加权 |
| `N_r` | `rend_normal` | rasterized Gaussian normal（world-space） | 未在 Python 中另做单位化 |
| `N_s` | `surf_normal` | 由 raster depth 重建的伪表面法线 | 乘了 `A.detach()`，故不会借 alpha 反传 |
| `D` | `rend_dist` | CUDA rasterizer 输出的 depth distortion map | 用于抑制一个像素内的深度混叠 |
| `d_xyz` | deformation 输出 | canonical Gaussian 的位置偏移 | warm-up 后才可能为张量 |
| `b` | `get_binary_feature(...)` | 动态/静态分离特征 | 仅非 PBR path 加入；Lambertian 阶段仍启用 |

仅当同时启用 `--gt_alpha_mask_as_scene_mask`、存在 RGBA alpha 且 `--white_background` 为真时，训练 RGB GT 才会被重组为

    G <- A_gt * G + (1 - A_gt) * background

来源：[train_stage1.py:733](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:733)。这并不是一个额外 loss，而是改变 RGB loss 的监督目标；黑背景实验（包括 0811）不走这段 RGB 重组，仍可独立使用 alpha BCE。

## 3. 非 PBR / Lambertian 的总目标

`render_mode=original_sh` 与 `render_mode=photometric_lambertian` 都走下面的非 PBR loss 骨架。区别只在 `I` 的颜色生成方式，以及 photometric 激活后是否有可学习光线平滑项。

    L_total = L_img + L_normal + L_dist
              + L_light_smooth + L_alpha
              + L_deform_xyz + L_binary (+ L_d_color，仅 original_sh)

其中各项均有开启条件；未开启时不应把它理解为“权重为小数的弱监督”，而是根本不加入总 loss。

### 3.1 主颜色项：L1 与 DSSIM

    L_L1    = mean(|I - G|)
    L_DSSIM = 1 - SSIM_11x11(I, G)
    L_img   = (1 - lambda_dssim) * L_L1 + lambda_dssim * L_DSSIM

默认 `lambda_dssim=0.2`，即默认权重为 0.8 L1 + 0.2 DSSIM。来源：[OptimizationParams](/home/han.li/reproduce/LumiMotion-perlight/arguments/__init__.py:125)、[loss 组合](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:784)、[L1/SSIM 实现](/home/han.li/reproduce/LumiMotion-perlight/utils/loss_utils.py:18)。

SSIM 使用每通道 11×11 Gaussian window，标准差 1.5，常数 `C1=0.01²`、`C2=0.03²`。所以它额外比较局部均值、方差和协方差，能抑制仅靠逐像素 L1 造成的局部结构漂移；但它不是法线监督，也不保持物理辐射线性。

对于当前 v5 Lambertian，`I` 是由 `linear_to_srgb(rendered_image_linear)` 得到。因此 RGB L1/SSIM 都是 sRGB 空间的 perceptual-style error，虽与输入 PNG/EXR 转出的显示域 GT 匹配，却会压低高亮线性辐射差的相对梯度。这个设计和“渲染先线性 compositing、后统一 gamma”一致，但不是纯线性 radiance loss。

### 3.2 raster normal 与 depth normal 的自一致性

    e_n(p) = 1 - <N_r(p), N_s(p)>
    L_normal = lambda_normal * mean(e_n)
    lambda_normal = 0.02, 仅在 iteration > start_normal_reg 且非 PBR 时

默认 `start_normal_reg=8000`。代码把 `lambda_normal` 写死为 `0.02`，它不是 `OptimizationParams` 的 CLI 参数；位置见 [train_stage1.py:714](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:714)。

这一项的正确名称应是“rendered normal—depth-derived normal consistency”，而非“normal GT loss”。`N_r` 是由 Gaussian local +Z、rotation 与 rasterizer 聚合得到；`N_s` 则是同一张渲染 depth map 通过 `depth_to_normal` 推导出的伪表面 normal。两者都来自模型自身，因而该项仅要求模型内部投影几何一致，不能判定其是否接近 Blender GT normal。

`surf_normal` 随后乘 `render_alpha.detach()`。detach 的含义是这条 normal 约束不会通过该乘法去改变 alpha；但它仍可对 depth、position、scale、rotation 等依赖路径反传。应注意 `N_r` 与 `N_s` 在低 alpha/背景区域的数值并非严格单位 normal，点积 loss 的数值尺度会被 alpha 调制。

### 3.3 depth distortion 正则

    L_dist = lambda_dist * mean(D), 仅在 iteration > start_normal_reg 且非 PBR 时

默认 `lambda_dist=1000`，来源：[arguments/__init__.py:139](/home/han.li/reproduce/LumiMotion-perlight/arguments/__init__.py:139)、[train_stage1.py:719](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:719)。`D` 是 rasterizer 产生的 per-pixel depth distortion buffer，而不是 GT depth error。

它的目的，是让同一像素内参与 alpha compositing 的 Gaussian 深度分布更集中，减少“沿视线多层半透明漂浮物”同时解释一个像素的退化。它因此间接改善几何表面与 normal 稳定性，但不提供任何 Blender mesh/EXR depth 的绝对几何锚点。

`1000` 本身不能说明这项一定主导训练：必须同 `mean(D)` 的原始量级相乘后才有意义。应使用 `--gradient_audit_interval N` 读取每项的加权梯度范数，而不是只看 TensorBoard 的总 loss。

### 3.4 前景 alpha BCE

有 GT alpha 时：

    L_alpha = lambda_alpha * BCE(A, A_gt)
    lambda_alpha = 0.1（默认）

没有 GT alpha 时：

    L_alpha = 0.001 * BCE(A, 1)

来源：[train_stage1.py:820](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:820)。这里 PyTorch `binary_cross_entropy` 逐像素比较 rasterized alpha 和导入的 RGBA alpha，soft alpha 可以保留抗锯齿边缘，而非强制硬二值轮廓。

对 clothV3 的训练，alpha 是直接的“前景与后景分离”约束。这一点比 RGB 背景重组更直接：前者约束 Gaussian coverage，后者只通过颜色间接产生边缘梯度。0811 的命令包含 `--gt_alpha_mask_as_scene_mask`，因此采用 0.1 × GT alpha BCE，而非背景全 1 的 fallback。

### 3.5 形变位置 L2 与 d_color 正则

当 `iteration > warm_up`、非 PBR 且 `d_xyz` 是 tensor 时：

    L_deform_xyz = d_xyz_loss_weight * mean(d_xyz²)

默认 `d_xyz_loss_weight=0.001`，来源：[train_stage1.py:842](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:842)。它使 temporal deformation 优先用小位移解释影像，避免无约束大范围移动 Gaussian。

`d_color` 的正则只在 **非 photometric active** 时存在：

    L_d_color = d_color_reg_loss_weight * mean(d_color[:,:3]²)

默认权重 0.01。这意味着 Lambertian 激活以后（当前默认从 10,001 iteration 起），`d_color` 不再进入 render 的物理颜色分支，也没有该正则；这是刻意避免把动态颜色残差作为光照/反照率的替代解释。

### 3.6 动态/静态 binary separation

当 `iteration > binarization_warm_up`、非 PBR 且未设 `no_binary_separation`：

    L_binary = lambda_separation * mean(b)

默认 `lambda_separation=0.005`。实现中为 `b ** 1`，即表面上等同 L1；实际对梯度的具体意义还依赖 `get_binary_feature()` 对 feature 的激活方式。来源：[train_stage1.py:862](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:862)。

它服务于动态/静态 Gaussian 分离，而不是 Lambertian BRDF。对于 0811，`binarization_warm_up=1000`，所以从 iteration 1001 起加入，并持续跨越 SH 与 Lambertian 两个阶段。

### 3.7 每帧 light direction 一阶平滑

仅 `photometric_active=True` 时执行：

    L_light_smooth = lambda_light_smooth1
                     * mean(||l_(t+1) - l_t||²)

默认 `lambda_photometric_light_smooth1=0.001`。`l_t` 先经 `F.normalize`，所以该项约束的是相邻帧单位光线方向的变化。来源：[photometric_lambertian.py:313](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_lambertian.py:313)、[train_step](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:794)。

`gt_directional` 与 `gt_point` 将 light table `requires_grad_(False)`，`learns_light=False`，故该项严格返回 0。0811 使用 `gt_point`，所以它在 log 中即使存在，也不会对参数产生梯度。只有 `learned_directional` 才会通过该项约束每帧光线表。

## 4. 训练阶段与 0811 历史实验的实际启用表

0811 的命令明确设定：`warm_up=500`、`binarization_warm_up=1000`、`start_normal_reg=8000`、`photometric_start_iter=10001`、`gt_alpha_mask_as_scene_mask=True`、`gt_point`。以下是该命令能回溯到的 loss schedule。

| iteration 区间 | renderer | 始终存在 | 新增项 | 不存在/不学习的项 |
|---|---|---|---|---|
| 1–500 | original SH | RGB、GT alpha BCE | 无 | d_xyz、binary、normal、dist、Lambertian light smooth |
| 501–1000 | original SH | RGB、alpha BCE、d_xyz L2、d_color L2 | 无 | binary、normal、dist |
| 1001–8000 | original SH | 上述 + binary | binary separation | normal、dist |
| 8001–10000 | original SH | 上述 | normal self-consistency、depth distortion | Lambertian 色彩/光线仍未启用 |
| 10001–35000 | Lambertian v4 `gt_point` | RGB、alpha BCE、d_xyz、binary、normal、dist | Lambertian shader 替换 SH | d_color L2；light smooth=0；GT normal loss=0 |

边界用的是严格的 `>`，所以 `start_normal_reg=8000` 时 normal/dist 从 **8001** 开始；`photometric_start_iter=10001` 的切换语义由 [photometric_active / update_photometric_state](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:284) 控制。0811 README 中给出的最佳测试指标发生在 10,000 iteration，仍位于 original SH 阶段，不能用作 Lambertian RGB loss 的验收结论。

## 5. 参数—梯度路径：每个 loss 真正会更新什么

~~~mermaid
flowchart LR
    RGB["RGB L1/DSSIM"] --> ALBEDO["photometric albedo"]
    RGB --> GEO["xyz / scale / opacity / rotation"]
    RGB --> DEF["Deform network"]
    RGB --> LIGHT["learned light only"]
    ALPHA["alpha BCE"] --> OPACITY["opacity"]
    ALPHA --> GEO
    NORMAL["normal-depth consistency"] --> ROT["rotation / normal orientation"]
    NORMAL --> DEPTH["xyz / scale / opacity via raster depth"]
    DIST["depth distortion"] --> DEPTH
    DXYZ["d_xyz L2"] --> DEF
    BINARY["binary separation"] --> FEAT["binary feature"]
    SMOOTH["light smoothness"] --> LIGHT
    GTN["GT normal EXR evaluation"] -. "不进入 backward" .-> NONE["无训练梯度"]
~~~

上图是依赖关系，不代表所有参数在每个阶段都被 optimizer 更新。`photometric_staged_training` 可在切换后冻结部分 Gaussian/deform group；其默认值为 `False`。另外，`gt_point` / `gt_directional` 不学习光，所以 RGB 也无法通过 light 参数改变结果。

当前代码提供梯度审计：`--gradient_audit_interval N` 会在第 1、每 N、最后 iteration 对加权 loss 项分别调用 `torch.autograd.grad`，把 position、rotation、scale、opacity、albedo（及 photometric normal）梯度范数写到 `loss_gradient_audit.csv`。实现见 [train_stage1.py:544](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:544)。这是判定 `1000 * mean(D)` 是否实际压制 RGB/alpha 梯度的可靠证据来源。

## 6. GT normal 为什么没有被优化

GT normal 的当前流程是：独立的 `scripts/eval_stage1_normals_gt.py` 渲染 Gaussian world normal，把 Blender GT normal 转成同一 world-space，并在 alpha/有效像素 mask 内计算角度差。该脚本不被 `scripts/train_stage1.py` import，训练函数也没有读取 normal EXR。

因此当前训练中存在三种完全不同的“normal”：

| normal | 来源 | 是否入 loss | 作用 |
|---|---|---|---|
| Gaussian shading/raster normal | local +Z 经 rotation、camera-facing 规则与 rasterization | 间接进入 RGB；进入 `L_normal` | 决定 Lambertian `n·l` 与输出 normal map |
| depth-derived pseudo normal | 模型的 raster depth | 进入 `L_normal` | 与 raster normal 做内部几何自一致性 |
| Blender GT normal | 每像素 EXR/转换数据 | 否 | 仅测试/审计指标 |

这意味着当前 normal metric 是**描述性/诊断性指标**，不是训练的因果目标。即便 `L_normal` 降低，也只证明两个模型输出彼此更一致，不能推出与 GT 的 angular error 下降。

要将它变成训练监督，至少需要定义：

1. 用 raster `A` 和 GT alpha 同时筛选可见前景，避免背景 zero vector；
2. 将 GT normal 变换到 renderer world-space，且复用评估脚本的符号/坐标规则；
3. 选择 camera-facing、raw outward 或 sign-invariant（`1-|dot|`）的语义；
4. 明确 `N_r` 是否除以 alpha 并重新 normalize，再计算 `1-dot`；
5. 设单独权重与 warm-up，并记录该项对 rotation/position 的梯度，以防压制 RGB 训练。

在这些条件没有实现和验证前，不应把 GT normal 文件悄悄塞入 loss；否则最常见的结果是把坐标/符号错误强行优化进 geometry。

## 7. PBR 模式是另一套目标，不能与 Lambertian 混读

`render_mode=photometric_perlight_pbr` 不使用前述 `L1 + DSSIM` 骨架。它以固定 geometry 的 photometric ablation 为目标：

    L_img_pbr = w_mse * MSE(I,G)
              + w_l1_fg * foreground_L1(I,G,A.detach())
              + w_dssim_fg * [1-SSIM(I*A, G*A)]
              + w_log * mean(sqrt((log(1+I_linear)-log(1+G_linear))² + 1e-6))

默认权重依次为 `1.0, 0.2, 0.1, 0.05`。PBR 再添加二阶 light smoothness、exposure L2、normal residual L2、roughness `(r-0.75)²`、environment energy 与 residual MLP L2。来源：[PBR image loss](/home/han.li/reproduce/LumiMotion-perlight/scripts/train_stage1.py:748)、[PBR regularizers](/home/han.li/reproduce/LumiMotion-perlight/scene/photometric_perlight_pbr.py:886)。

关键差异：PBR 分支不加入 alpha BCE、normal-depth consistency、depth distortion、`d_xyz` 与 binary separation；而且训练入口要求 `photometric_start_iter >= densify_until_iter`，用以保证每 Gaussian normal residual 的参数形状稳定。0811 不是 PBR 实验，因此不应把这些 PBR loss 当成它的训练约束。

## 8. 审计结论与当前风险

| 检查项 | 判定 | 解释 |
|---|---|---|
| RGB 监督 | PASS | L1+DSSIM 的公式、GT 图、色彩范围和反传路径明确 |
| 前景/后景分离 | PASS（0811） | 0811 使用 GT alpha BCE，权重 0.1 |
| depth/normal 正则含义 | PASS，需正名 | 是模型内部 self-consistency，不是 GT geometry/normal supervision |
| GT normal 对比 | PASS（仅评估） | 不进入 train loss，避免误把评价当监督 |
| 学习光线的平滑 | 条件成立 | 仅 learned_directional 有效；0811 gt_point 等于 0 |
| normal regularizer 可配置性 | FAIL / 可复现风险 | `lambda_normal=0.02` 写死，无法通过标准 CLI/`cfg_args` 明示覆写 |
| distortion 权重可解释性 | 未验收 | 默认权重 1000 很大，必须结合 raw value 和 gradient audit 判断 |
| soft alpha 数据语义 | 有风险 | RGB 的 alpha premultiplication 路径曾出现 alpha-squared 风险；这会改变 RGB loss，不改变 BCE 的 GT alpha 本身 |
| 0811 的 Lambertian RGB 结论 | FAILED 作为物理 RGB 验收 | 该 checkpoint 的 `gt_point + intensity=1` 在 `/pi` 与 `1/r²` 后理论上近黑；其历史 README 已将其保留为失败对照 |

## 9. 建议的下一步

1. 对下一次 clothV3 Lambertian 训练开启 `--gradient_audit_interval 500`，在 8,001、10,001、20,000、35,000 比较每个**加权** loss 对 rotation、xyz、opacity、albedo 的梯度 RMS。
2. 把写死的 `lambda_normal=0.02` 提升为有默认值的 CLI 参数，并把 raw normal loss、raw dist loss、加权 loss 逐项写入 TensorBoard；这样才可复现损失配方。
3. 在不改变主训练目标的前提下，先实现只记录的 GT normal loss（不反传），验证 world/camera-facing/sign-invariant 三种定义的量级，再决定是否加入训练。
4. 如果加入 GT normal supervision，先固定 geometry 或小权重只更新 rotation/independent normal，做与无监督版本完全相同 seeds 的 ablation；不能与光强、alpha 处理、densification 改动混在一个实验里。
5. 针对 alpha，分别记录 `mean(A)`、`BCE(A,A_gt)`、前景/背景分区 RGB L1，确保“前景分离正确”与“RGB 被重复乘 alpha”两个问题不会混淆。
