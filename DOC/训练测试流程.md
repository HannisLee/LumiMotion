# 训练测试流程

本文是 Stage1 训练、评测和光照诊断的流程模板。具体参数不在本文硬编码维护，而是先手工选择对应版本的参数文档，再把里面的训练参数复制到本文命令模板中。

本文不要理解成必须跑完整数据集；每次可以只跑一个场景、几个场景，或只做评测/导出。

## 1. 使用方式

先确认当前要跑的版本，再打开对应参数文档：

```text
版本总览 -> DOC/version.md
V1   -> DOC/LH-static-stage1V1.md
V2   -> DOC/LH-static-stage1-V2.md
V3.1 -> DOC/stage1-V3.1-参数.md
```

执行前手工确定：

```bash
SCENE=brass_vase
GPU=0
CONDA_ENV=lumimotion-cu126
OUT_ROOT=output/LH-staticv3.1
EXP_NAME=${SCENE}_stage1v31
MODEL=${OUT_ROOT}/${EXP_NAME}_static
PARAM_DOC=DOC/stage1-V3.1-参数.md
```

说明：

- `PARAM_DOC` 只是记录本次使用哪份参数说明，命令不会自动读取它。
- `--model_path` 传不带 `_static` 后缀的 `${OUT_ROOT}/${EXP_NAME}`；训练脚本会根据 `--deform-type static` 自动追加 `_static`。
- `MODEL` 必须写成实际输出目录，也就是带 `_static` 后缀的路径。
- 新服务器 `minakshi` 默认用 `lumimotion-cu126`；旧服务器用 `lumimotion-cu129`。
- 所有命令从仓库根目录执行，输出必须放在 `output/` 下。

## 2. Stage1 训练

先从 `PARAM_DOC` 复制对应版本的参数块，再填入下面模板。下面示例使用 V3.1；如果跑 V1/V2，请以对应 md 为准，不要混用不同版本的 smooth 参数。

```bash
SCENE=brass_vase
GPU=0
CONDA_ENV=lumimotion-cu126
OUT_ROOT=output/LH-staticv3.1
EXP_NAME=${SCENE}_stage1v31

CUDA_VISIBLE_DEVICES=${GPU} conda run --no-capture-output -n ${CONDA_ENV} \
python -m scripts.train_stage1 \
  --source_path data/LH-data/transfer-static/${SCENE} \
  --model_path ${OUT_ROOT}/${EXP_NAME} \
  --images images \
  --train_light_folder images \
  --is_blender --eval --gt_alpha_mask_as_scene_mask \
  --render_mode photometric_lambertian \
  --photometric_stage s1d_joint \
  --photometric_light_param per_frame \
  --photometric_init_r_xy 0.8 \
  --photometric_init_z 0.6 \
  --photometric_multistart_enabled \
  --photometric_multistart_num_phases 16 \
  --photometric_multistart_short_iters 1000 \
  --photometric_s1d_light_lr 0.0001 \
  --photometric_s1d_albedo_lr 0.001 \
  --photometric_s1d_rotation_lr 0.0001 \
  --photometric_s1d_scaling_lr 0.0001 \
  --photometric_s1d_position_lr 0.0 \
  --photometric_s1d_deformation_lr 0.0 \
  --photometric_s1d_opacity_lr 0.0 \
  --photometric_use_hemi_prior \
  --lambda_photometric_light_smooth1 0.001 \
  --lambda_photometric_light_smooth2 0.001 \
  --lambda_photometric_hemi 0.001 \
  --lambda_photometric_albedo_prior 0.005 \
  --deform-type static \
  --resolution 2 \
  --iterations 35000 \
  --densify_until_iter 8000 \
  --opacity_reset_interval 100000 \
  --min_opacity 0.005 \
  --binarization_warm_up 1000 \
  --lambda_separation 0.005 \
  --d_xyz_loss_weight 0.001 \
  --d_color_reg_loss_weight 0.01 \
  --depth_ratio 1.0 \
  --test_iterations 1000 5000 10000 20000 30000 35000 \
  --save_iterations 1 1000 5000 10000 20000 30000 35000 \
  --quiet
```

训练完成后检查：

```bash
MODEL=${OUT_ROOT}/${EXP_NAME}_static

test -f ${MODEL}/point_cloud/iteration_35000/point_cloud.ply
test -f ${MODEL}/deform/iteration_35000/deform.pth
test -f ${MODEL}/photometric/iteration_1/photometric.pth
test -f ${MODEL}/photometric/iteration_35000/photometric.pth
```

`photometric/iteration_1/photometric.pth` 很重要：它是初始化后的 photometric 权重，用来检查初始 light trajectory 是否符合预期。训练命令的 `--save_iterations` 必须包含 `1`；当前脚本也会自动补 `1`，但命令里仍建议显式写出，避免流程文档和实际诊断脱节。

## 3. Stage1 评测

评测也按手工指定的 `SCENE`、`MODEL`、`LOAD_ITER` 执行，不要求跑全部场景。

```bash
SCENE=brass_vase
GPU=0
CONDA_ENV=lumimotion-cu126
MODEL=output/LH-staticv3.1/${SCENE}_stage1v31_static
LOAD_ITER=35000

CUDA_VISIBLE_DEVICES=${GPU} conda run --no-capture-output -n ${CONDA_ENV} \
python -m scripts.eval_stage1_dynamic \
  --source_path data/LH-data/transfer-static/${SCENE} \
  --model_path ${MODEL} \
  --images images \
  --train_light_folder images \
  --is_blender --eval \
  --resolution 2 \
  --render_mode photometric_lambertian \
  --deform_type static \
  --load_iter ${LOAD_ITER}
```

主要输出：

```text
${MODEL}/results_stage1_dynamic.json
${MODEL}/eval_stage1_dynamic/ours_<LOAD_ITER>/
```

常看图片：

```text
${MODEL}/eval_stage1_dynamic/ours_<LOAD_ITER>/*_comparison.png
${MODEL}/eval_stage1_dynamic/ours_<LOAD_ITER>/*_render.png
${MODEL}/eval_stage1_dynamic/ours_<LOAD_ITER>/*_albedo.png
${MODEL}/eval_stage1_dynamic/ours_<LOAD_ITER>/*_normal.png
```

如果只需要检查某次训练，不要写批量循环；手动改 `SCENE` 和 `MODEL` 更安全。

## 4. 光照导出与可视化

导出读取：

```text
${MODEL}/photometric/iteration_<ITER>/photometric.pth
```

`ITERS` 必须包含 `1`，这样可以画出初始化点和初始化轨迹。推荐最小集合：

```bash
ITERS="1 1000 5000 10000 20000 30000 35000"
```

单场景导出模板：

```bash
SCENE=brass_vase
CONDA_ENV=lumimotion-cu126
MODEL=output/LH-staticv3.1/${SCENE}_stage1v31_static
LIGHTS_JSON=data/LH-data/static/${SCENE}/lights.json
ITERS="1 1000 5000 10000 20000 30000 35000"

for ITER in ${ITERS}; do
  CKPT=${MODEL}/photometric/iteration_${ITER}/photometric.pth
  if [ ! -f "${CKPT}" ]; then
    echo "[skip] missing ${CKPT}"
    continue
  fi

  CSV=${MODEL}/light_directions_it${ITER}.csv
  POLAR=${MODEL}/light_polar_compare_it${ITER}.png
  CURVE=${MODEL}/light_timeseries_compare_it${ITER}.png
  LOSS=${MODEL}/light_direction_loss_it${ITER}.txt

  conda run --no-capture-output -n ${CONDA_ENV} \
  python -m LH_Utils.export_light_directions \
    --model_path ${MODEL} \
    --iteration ${ITER} \
    --output ${CSV}

  conda run --no-capture-output -n ${CONDA_ENV} \
  python -m LH_Utils.plot_light_polar \
    --csv ${CSV} \
    --lights_json ${LIGHTS_JSON} \
    --output ${POLAR} \
    --title "${SCENE} light polar iteration ${ITER}"

  conda run --no-capture-output -n ${CONDA_ENV} \
  python -m LH_Utils.plot_light_timeseries \
    --csv ${CSV} \
    --lights_json ${LIGHTS_JSON} \
    --output ${CURVE} \
    --title "${SCENE} light xyz iteration ${ITER}"

  conda run --no-capture-output -n ${CONDA_ENV} \
  python -m LH_Utils.light_direction_loss \
    --csv ${CSV} \
    --lights_json ${LIGHTS_JSON} \
    --output ${LOSS}
done
```

每个 iteration 输出：

```text
${MODEL}/light_directions_it<ITER>.csv
${MODEL}/light_polar_compare_it<ITER>.png
${MODEL}/light_timeseries_compare_it<ITER>.png
${MODEL}/light_direction_loss_it<ITER>.txt
```

CSV 有 6 列：

```text
raw_x, raw_y, raw_z, dir_x, dir_y, dir_z
```

说明：

- `it1` 用来看初始化，不代表训练收敛结果。
- 如果是从 `--load_iter 30000` 进入 photometric 子阶段，初始化 photometric 权重可能写到 `photometric/iteration_30001/photometric.pth`，此时也应把 `30001` 加进 `ITERS`。
- 如果某个 iteration 没有 photometric checkpoint，循环会跳过；这通常说明该 iteration 没有保存 photometric 权重。

## 5. 手工多场景模板

如果要跑多个场景，手工列出本次确实要处理的场景，不要默认全量：

```bash
SCENES="brass_vase concrete_cat"
CONDA_ENV=lumimotion-cu126
OUT_ROOT=output/LH-staticv3.1
EXP_SUFFIX=stage1v31
ITERS="1 1000 5000 10000 20000 30000 35000"

for SCENE in ${SCENES}; do
  MODEL=${OUT_ROOT}/${SCENE}_${EXP_SUFFIX}_static
  LIGHTS_JSON=data/LH-data/static/${SCENE}/lights.json

  for ITER in ${ITERS}; do
    CKPT=${MODEL}/photometric/iteration_${ITER}/photometric.pth
    if [ ! -f "${CKPT}" ]; then
      echo "[skip] ${SCENE} iteration ${ITER}"
      continue
    fi

    conda run --no-capture-output -n ${CONDA_ENV} \
    python -m LH_Utils.export_light_directions \
      --model_path ${MODEL} \
      --iteration ${ITER} \
      --output ${MODEL}/light_directions_it${ITER}.csv

    conda run --no-capture-output -n ${CONDA_ENV} \
    python -m LH_Utils.plot_light_polar \
      --csv ${MODEL}/light_directions_it${ITER}.csv \
      --lights_json ${LIGHTS_JSON} \
      --output ${MODEL}/light_polar_compare_it${ITER}.png \
      --title "${SCENE} light polar iteration ${ITER}"

    conda run --no-capture-output -n ${CONDA_ENV} \
    python -m LH_Utils.plot_light_timeseries \
      --csv ${MODEL}/light_directions_it${ITER}.csv \
      --lights_json ${LIGHTS_JSON} \
      --output ${MODEL}/light_timeseries_compare_it${ITER}.png \
      --title "${SCENE} light xyz iteration ${ITER}"

    conda run --no-capture-output -n ${CONDA_ENV} \
    python -m LH_Utils.light_direction_loss \
      --csv ${MODEL}/light_directions_it${ITER}.csv \
      --lights_json ${LIGHTS_JSON} \
      --output ${MODEL}/light_direction_loss_it${ITER}.txt
  done
done
```

## 6. 快速检查清单

- 是否选定了对应参数 md，而不是从旧文档复制过期参数。
- `--model_path` 是否不带 `_static`，而 `MODEL` 是否带 `_static`。
- `--save_iterations` 和 `ITERS` 是否都包含 `1`。
- V3.1 是否传入 `--photometric_light_param per_frame`，且没有再依赖 `--photometric_num_ctrl_points`。
- V3.1 是否按需要开启 `--photometric_multistart_enabled`，并使用 `--photometric_multistart_num_phases 16`。
- V3.1 是否同时记录 `--lambda_photometric_light_smooth1` 和 `--lambda_photometric_light_smooth2`。
- 所有输出是否都在 `output/` 下。
- 评测和导出是否只处理本次需要的 `SCENE`，不要误跑全数据集。
